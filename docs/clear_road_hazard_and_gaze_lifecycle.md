# M2 위험사건과 시선 창 수명 수정 (2026-10-20)

이번 범위는 교수님 요구 중 1번(앞차 없는 목표속도 사건), 2번(경고/인수 요청), 5번(GetClientRect 오류)이다. `run_pilot.cmd`의 M2는 `ClearRoadM2Hazard`를 사용한다. 과거 앞차 이동 구현은 이전 데이터/회귀 테스트를 위한 코드로 남아 있으나 통합 실행의 사건 생성에는 사용하지 않는다.

## 사건 조건

| 항목 | 적용 값/정의 |
|---|---|
| 후보 시점 | 기존처럼 M2 활성시간 400~600초에서 seed로 한 번 추첨 |
| 검사 시작 | 후보 시점 6초 전 |
| 목표속도 | `MovingHazardConfig.target_speed_kmh`를 지정하면 해당 값. 기본은 현재 도로 제한속도(현재 전용 TM의 속도 차감 기본값 0%와 일치). 차량 속도를 강제로 변경하지 않음 |
| 허용 오차 | 목표속도 ±5 km/h |
| 안정 구간 | 2초 연속, 관측 간격 0.25초 초과 시 다시 시작 |
| 재검사 | 1초마다 앞쪽 현재 차로 경로/교통 확인, 제시 직전 재확인 |
| 앞차 | 생성하지 않음. 장애물 앞뒤 여유를 포함한 전방 경로에 차량이 있으면 보류 |
| 장애물 | 현재 주행 차로 전방에 `static.prop.box01` 1개. 약 4초 TTC를 차량/장애물 외곽 간 거리로 산출 |
| 제시 | 지하에 준비해 실제 크기와 TM 제외 쌍을 먼저 확보한 뒤, 조건 충족 시 도로 위로 한 번 배치. 앞차 가림/차로변경은 사용하지 않음 |
| 배치 확인 | 다음 CARLA 스냅샷으로 정지·위치 확인. 1초 내 확인 실패 시 사건 무효, 주행 계속 |
| 조건 미충족 | 600초까지 보류 후 미발생. 같은 M2에서 늦은 재실행 없음 |

고정 목표속도를 정하면 동일 값을 MANUAL/NoA에 사용해야 한다. 기본 참조는 현재 도로 제한속도이므로 실행별 `target_speed_kmh`와 실제 노출 속도를 함께 확인해야 한다. 수동 운전 중 가속/제동/조향을 대신하지 않는다.

진출과 위험사건의 설정 시간 구간은 그대로다. 실제 진출 지원 또는 일반 차선
변경이 진행되는 동안 장애물을 제시하지 않는 상호 배제 조건을 유지한다.
진출 기회를 벗어났는데도 `CONFIRMED`가 남는 경우는 연속 물리 관측으로
종료 처리한다(`docs/signal_confirmed_module_exit.md`의 설정표 참조).
그 뒤에도 목표속도·전방 차량 없음·2초 안정 주행 등을 다시 통과해야 한다.
조건이 600초까지 성립하지 않으면 미발생으로 기록하고 실험은 계속한다.

## 경고와 제어

- 실제 전방 카메라의 장애물 노출 후보 프레임을 확인한 다음 화면에 `충돌 경고 · 전방 장애물!`을 표시한다. NoA가 켜져 있으면 `직접 운전해 주세요 (인수 요청)`을 함께 표시한다. 수동 상태에는 충돌 경고만 표시한다.
- 시각 경고는 최대 5초이며 통과/충돌/사건 오류 시 해제된다. 별도 경고음은 이번 변경에 포함하지 않는다.
- 장애물 노출 flip과 경고 flip은 별도로 기록한다. 경고 시각을 장애물 시각과 같다고 가정하지 않는다.
- 경고 코드는 입력 이벤트를 읽거나 NoA 상태/차량 제어를 변경하지 않는다. 기존 NoA 해제 조건과 깜빡이 일반 차로변경/진출 동작을 유지한다.
- 새 장애물과 ego의 TM 감지 쌍만 제외한다. 물리적 충돌은 유지한다. 전용 TM 원본 `ALSM.cpp`에서는 미등록 차량/보행자에만 충돌용 경로 격자를 만들고 이 static prop에는 만들지 않는다. 네이티브 바이너리는 변경하지 않았다.
- 자동 회피 제동/조향을 추가하지 않는다. 일반 TM의 기존 곡선/교통 감속은 유지된다. 사건 후 자동제어 brake readback이 관측되면 원인을 단정하지 않고 분석 적격 여부에 표시한다.
- 장애물 충돌 후 안내·SPACE 확인·부분 M2 및 충돌 결과 저장·종료 절차는 유지한다. 사건/로그 오류는 실험의 강제 종료 사유가 아니다.

## 저장되는 증거

- 기존 `events.csv`의 `m2_hazard_*`와 원본 입력 배치를 유지한다.
- `scheduled`, `preparation_deferred`, `obstacle_reveal_requested`, `geometric_exposure`, `display_candidate`, `warning_displayed`, `end`에 정책/목표·실제 속도/차로/경고 시각/실패 이유를 기록한다.
- 최종 위험사건 기록에 `exposure_policy`, `target_speed_kmh`, `readiness_tuning`, `warning`, `warning_errors`, `automatic_avoidance`를 추가한다.
- 반응 집계의 원본 반응시간은 유지하고, 새로운 사건에서 경고 누락·사건 무효·자동제어 제동 readback이 있으면 `experimental_condition_issues`를 기록하고 `analysis_reaction_time_s`는 null로 둔다.

2026-10-20 준비 조건 로그 보완(`P8_CLEAR_ROAD_EXIT_INTERLOCK_V3`):

- `m2_hazard_readiness_evaluated`는 준비 재시도 시점(기존 1초 주기)에 기록한다.
  진출/차선 변경 충돌, 주행 조건, 발생 시간 창, 예정 시각 도달, 목표속도 조회,
  속도 허용 범위, 전방 경로, 교차로, 전방 차량, 카메라, 안정 유지 시간을
  `checks`에 분리한다. 상태는 `PASS`/`FAIL`/`NOT_CHECKED`/`ERROR`이다.
- 앞 단계에서 막힌 검사는 `NOT_CHECKED`와 차단 사유를 남긴다.
  이때 `target_speed_kmh=null`은 속도 불충족의 증거가 아니다.
  `target_source`는 값 조회 전에도 명시하며, 지나간 시도의 통과 값을
  이번 시도의 결과로 재사용하지 않는다.
- 관측 시각·프레임, 실제 속도, 진출 상태와 의사 입력 결과, 경로 요청 여부,
  전방 차단 차량 ID(관측된 경우)를 함께 남긴다.
- `m2_hazard_preparation_deferred.readiness`와 최종 기록의 `last_readiness`에도
  마지막 조건 결과가 들어간다. 신규 진단 로그 저장 오류는 메모리에 보존하고
  최종 기록의 `nonfatal_recording_errors`에 남긴다. 이 오류로 위험사건 준비나
  실험을 중단하지 않는다. 기존 연구 이벤트 CSV와 최종 결과 내보내기 경로를
  사용하므로 결과 ZIP에도 포함된다.

## 시선 창 수명

주행 창의 `pygame.quit()` 이전에 시선 관측 종료시각을 고정하고 수집 중지 신호를 보낸다. 지연 도착한 원본은 보존하되 종료 뒤 샘플로 주시 시간을 늘리지 않는다. 전체화면 전환 전에 이전 창 매핑을 비우고 새 창에서 좌표를 다시 읽는다.

정상 종료/전환 도중의 창 조회는 `PRESENTATION_ENDED`/`PRESENTATION_CHANGED` 등으로 미매핑 처리한다. 활성 창에서 실제로 발생한 `GetClientRect` 오류, SDK/저장 오류는 그대로 오류 목록과 `FAILED`에 남긴다. `COLLECTED`는 원자료 수집 상태이며 AOI 보정 합격을 의미하지 않는다. AOI/모니터/태블릿 배치와 합격 기준은 바꾸지 않았다.

## 검증

진출 상태 잔류/조건별 로그 보완 관련 오프라인 회귀: **567건 통과, 1건 건너뜀**.
기존 파일럿의 늦은 예정 시각(598.7594초)을 사용한 모의 시나리오에서,
종료되지 않은 진출 동의 상태를 정리한 뒤 시간 창 내 장애물이 등장함을 확인했다.
실제 차선 변경 중 보류, 일시적 경로 누락 시 진출 유지, 경로 취소 실패 시
보류·주행 계속, 새 진단 로그 오류 시 사건 계속, 핸들/페달/NoA 조건 및
충돌 후 부분 기록 ZIP 회귀도 포함한다. 원본 파일럿을 실기기로 재실행한 결과는
아니며, 다음 파일럿에서 진출 종료 기록과 실제 장애물 노출을 확인해야 한다.
결과: `data/exit_hazard_verification/summary.json`.

자동 검증 산출물: `data/clear_road_verification/`. 가상 CARLA 월드와 SDL dummy에서 수행하며, 테스트 하네스는 실제 CARLA Client 및 물리 핸들 연결을 금지한다. 실제 장비의 영상 노출·속도·경고·종료 후 summary는 다음 파일럿에서 확인해야 한다. Unreal/드라이버/OS의 비정상 종료까지 자동 테스트가 보장하지는 않는다.

최종 결과: 전체 2,496개 중 2,489개 통과, 2개 건너뜀, 5개 실패. 실패 5개는 이전 `data/signal_exit_verification/summary.json`의 미러 배치/콕핏 위치 기대값 불일치와 정확히 같다. 이번 관련 집중 검증 55개(신규 31개 포함)는 모두 통과했다. 충돌 확인 종료 및 부분 기록 ZIP, 오류 주입 후 계속 주행, 현재 차로/속도/TTC, 정상 창 종료/전환과 실제 매핑 실패 구분, 경고 기록과 분석 제외를 확인했다.

전용 NoA 바이너리 SHA-256은 이전과 같은 `f69e59a5298414f68ec1a27d2d5f820961fc0a7d3a9f0195c4dac6977e43a0b5`이다. 결과 목록과 비교 판정은 `data/clear_road_verification/summary.json`, 전체 출력은 `full_unrestricted.txt`, 기계 판독 결과는 `full_unrestricted.xml`에 있다.
