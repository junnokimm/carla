# 차선 내부 NoA 활성화 (2026-10-20)

`run_pilot.cmd`의 훈련·M1·M2에서 차량 전체가 현재 주행 차선 안에 있으면,
중앙에서 20cm 넘게 벗어났다는 이유만으로 NoA 활성화를 거절하지 않는다.
차량 중심점뿐 아니라 bounding box의 폭·길이·중심 오프셋·회전과 차량 진행 각도를
반영하는 기존 차선 포함 검사를 유지한다.

## 적용 조건

| 항목 | 동작 |
|---|---|
| 차선 내부에서 중앙을 벗어남 | 활성화 허용 |
| 차량 앞뒤 모서리 또는 차체가 차선 경계를 넘음 | `VEHICLE_STRADDLING`, 수동 주행 유지 |
| 주행 방향 정렬 | 기존 0.1rad(약 5.7도) 허용 범위 유지 |
| 차선 정보 없음·유효하지 않은 차량/차선 치수 | 기존 실패 사유 기록, 수동 유지 |
| 차선 변경 중·외부 비가용 상태 | 기존 활성화 제한 유지 |
| 브레이크 입력 | 기존 0.05 이상 활성화 차단·NoA 해제 유지 |
| 핸들 조작·해제 버튼 | 기존 NoA 해제 조건 유지 |
| 일반 깜빡이 차선 변경의 시작·완료 판정 | 기존 중앙 0.2m 정렬 조건 유지 |

예를 들어 폭 3.5m 차선에서 폭 1.8m 차량이 차선과 평행하고 bounding box 중심
오프셋이 없으면, 중앙에서 좌우 약 0.85m까지 차체가 들어온다. 실제 허용 거리는
차량 치수와 기울기마다 달라진다. 이 예시 값을 고정 허용치로 사용하지 않는다.

## 구현과 기록

- `AutomationInteractionConfig.require_centered_activation`은 기존 호출자의
  동작을 보존하도록 기본값 `True`이며, P8 통합 실행에서 `False`를 설정한다.
- 활성화 게이트만 중앙 정렬 검사를 생략한다. 같은 기하 함수를 사용하는
  차선 변경 시작·완료 판정은 기본적으로 중앙 정렬을 계속 검사한다.
- 새 RPC나 주행 루프, 조향 명령을 추가하지 않는다. 기존 bounding box 캐시와
  활성화 요청 시 재확인 경로를 사용한다.
- `session_manifest.json`의 `components.automation_interaction_policy`에 실제
  적용한 설정을 저장한다. `center_tolerance_m=0.2`가 함께 저장되지만,
  `require_centered_activation=false`이면 활성화 중앙 제한에는 사용하지 않는다.
  해당 0.2m 값은 차선 변경 정렬 판정에 계속 사용된다.
- 조향·속도 제어, 주행 입력, 진출·위험사건 및 기존 오류 복구 경로는 변경하지 않는다.

사용 중인 네이티브 빌드의 Traffic Manager 소스에는 조향 출력의 프레임 간 변화량
제한이 있다. 이번 변경은 그 제어기나 바이너리를 수정하지 않는다. 이 코드 확인은
실주행에서 좌우 흔들림이 없다는 검증을 대신하지 않는다.

## 검증

관련 오프라인 회귀 검사 973건 통과, 기존 심볼릭 링크 권한 검사 1건 건너뜀.
새 활성화·경계·기울어진 차체·모듈 연결·정책 저장 검사 38건을 추가했고,
기존 제어 전환 검사에 좌우 0.6m 위치에서 핸들·브레이크·버튼으로 해제한 직후
수동 명령이 전송되는 6건을 추가했다.

기존 차선 변경·자동 소등·진출 선행·위험사건·충돌 후 SPACE 확인·ZIP 저장도 검사했다.
CARLA 서버 연결과 실제 조이스틱 접근을 금지하는 오프라인 실행기를 사용했다.
결과: `data/noa_within_lane_verification/summary.json`,
`data/noa_within_lane_verification/regression.xml`.

다음 통합 실행에서 차선 내부 좌우 위치의 NoA 활성화, 차선 경계 걸침 시 거절,
활성화 후 중앙 복귀의 안정성, 기존 핸들·브레이크 해제를 확인한다.
실제 언리얼·핸들 주행 검증은 아직 수행하지 않았다.
