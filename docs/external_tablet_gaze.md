# 외부 태블릿 AOI와 시간 기록

`run_pilot.cmd`의 기존 시선 수집에 외부 태블릿 분류를 연결했다.
주행·핸들·NoA·위험사건 코드는 변경하지 않았다. 추가 처리는 시선 수집
스레드와 별도 Tobii 프로세스에서 수행하며 렌더링 프레임 훅은 변경하지 않았다.
SDK, 매핑 또는 저장 오류는 시선 수집 실패로 기록하며 실험 종료를 요청하지 않는다.

## 현재 매핑의 의미

현재 `config/p8_gaze.json`은 `config/p8_external_tablet_20261019_070521.json`을 사용한다.
태블릿을 더 왼쪽·위쪽으로 옮긴 뒤 검사한
`data/gaze_recheck/20261019T070521Z-29b5a008`의 실제 좌표로 만든 **임시·부분 매핑**이다.
이전 배치의 `config/p8_external_tablet.json`은 비교용으로 보존했다.
모니터 표시 평면의 연장 좌표를 사용하며, 태블릿의 물리적 3차원 좌표를 측정한 것은 아니다.
모니터 밖 좌표도 SDK가 유효하다고 반환하면 사용할 수 있다.
기존 모니터 좌표 디코더의 유효성 규칙은 유지하고, 태블릿 분류에서만 이를 별도로 사용한다.

- 좌우 눈별로 관측한 좌표의 볼록 다각형을 사용한다. 처음/끝 2초를 제외하고,
  각 지점·눈에 60개 이상 유효 샘플이 있어야 사용한다. 좌표별 1–99 백분위에
  정규화 좌표 0.01의 여유를 둔다. 관측한 지점 사이의 내부는 보간 영역이다.
- 현재 매핑은 오른쪽 위를 포함해 다섯 지점에서 관측한 좌표를 사용한다.
  오른쪽 아래는 왼쪽 눈만 관측되었다. 아직 독립 재검증 전이며,
  새로운 피험자에서 같은 정확도를 보장하는 매핑이 아니다.
- 두 눈이 유효하면 둘 다 각자의 태블릿 영역에 들어와야 한다. 한쪽 눈만 유효하면
  그 눈으로 분류하되 단안 기록을 구분한다. 눈 사이 또는 화면 AOI와 충돌하면 미확인 처리한다.
- 실험 구간 시작 시 SDK에서 읽은 장비 일련번호·표시 영역을 프로필과 대조한다.
  불일치·조회 실패·프로필 오류 시 태블릿 분류를 하지 않고 원본/모니터 시선 수집은 계속한다.
  물리적인 Nano·태블릿 이동은 소프트웨어로 자동 감지할 수 없다.

장비 위치와 ETM 표시 영역은 유지하고, 피험자별 ETM 보정과 짧은 영역 확인을 수행한다.
장비를 옮겼다면 다시 검사하고 새 프로필을 만들어야 한다. 실험 중 ETM 설정을 변경하지 않는다.
기존 검사에 다시 적용한 결과는 구현 점검이며 독립적인 정확도 검증은 아니다.

## 실행 및 결과

PowerShell에서 평소처럼 실행한다.

```powershell
cd C:\dev\carla
.\run_pilot.cmd
```

시작 로그의 `TABLET_MAPPING_STATUS`에서 `binding`이
`DISPLAY_BINDING_MATCHED_AT_CAPTURE_START`인지 확인한다. 이는 장비 설정의 일치이며
피험자 시선의 정확도 검증 완료를 뜻하지 않는다. `--no-gaze`를 주면 수집하지 않는다.

결과 루트는 `data/p8_operator/<Run ID>/`이다.

| 파일 | 내용 |
| --- | --- |
| `gaze_totals.json` | 저장 완료된 훈련·M1·M2 시선 구간별 결과와 합계 |
| `gaze/<구간-식별자>/summary.json` | 해당 구간의 시간, 추적 상태, 매핑 상태와 오류 |
| `gaze/<구간-식별자>/gaze.jsonl` | 샘플별 `aoi=TABLET`, 단안/양안, 원본 좌표, 분류 이유; 사용한 프로필 사본과 해시 |
| `gaze/<구간-식별자>/intervals.jsonl` | 상태별 시작/끝 시각 및 지속 시간, 추적 손실·누락 구간 |
| `gaze/<구간-식별자>/raw_gaze.jsonl` | SDK 원본과 실시간 표시 영역 확인 결과 |

완료된 파일은 기존 결과 ZIP에도 들어간다. 종료가 지연된 수집기는 `.gaze_pending`에 남으며
합계·ZIP에서는 제외된다. 휴식·안내 등 시선 수집기가 없는 시간은 합계에 포함되지 않는다.
구간 중 수집기만 먼저 실패하면 해당 구간이 끝날 때까지를 `NO_DATA`로 남긴다.

## 몇 초 보았는가

`gaze_totals.json`의 `tablet_classified_seconds`가 **태블릿으로 분류된 관측 시간(초)**이다.
`seconds_by_state.TABLET_BINOCULAR`와 `TABLET_MONOCULAR`의 합이다. 실제 총 태블릿 주시
시간을 확정한 값은 아니므로 `true_total_tablet_seconds`는 `null`로 남긴다.

| 상태 | 의미 |
| --- | --- |
| `TABLET_BINOCULAR` / `TABLET_MONOCULAR` | 양안 / 단안으로 태블릿이라 분류된 시간 |
| `TRACKING_LOST` | 양쪽 눈 모두 유효 좌표를 제공하지 않은 시간 |
| `NO_DATA` | 콜백 중단, 시퀀스 누락, 시계 이상, 수집 시작 전·종료 후의 미관측 시간 |
| `VALID_UNMAPPED` | 눈은 추적되지만 정의한 영역으로 분류하지 못한 시간 |
| `AOI_UNCERTAIN` | 두 눈의 태블릿 판정 또는 화면 AOI 판정이 충돌한 시간 |
| `MAPPING_UNAVAILABLE` | 창·모니터·포커스 등 매핑 조건을 확인하지 못한 시간 |
| `TRANSITION_UNCERTAIN` | 인접 샘플의 상태가 달라 전환 시점을 확정할 수 없는 시간 |

동일 상태인 인접 샘플 사이만 합산한다. 시퀀스가 연속이고 장치 시각과 콜백 시각 간격이
각각 100ms 이하여야 한다. 손실·영역 전환 구간을 앞뒤 태블릿 주시로 메우지 않는다.
시간 기준은 SDK 콜백에서 이미 기록하는 고해상도 `perf_counter_ns`이다. 기존 Python 3.10의
`monotonic_ns`는 이 장비에서 해상도가 낮아 서로 다른 샘플에 같은 시각을 붙이는 경우가 있어
기간 계산에는 쓰지 않는다. 두 시계의 원점을 직접 혼용하지 않으며 세션 상대 시각만 시작 시점
시계 쌍으로 근사 연결한다. Windows Python 3.10부터 성능 카운터가 프로세스 간 공유되는 점은
[Python 공식 문서](https://docs.python.org/3.10/library/time.html#time.perf_counter)에 명시되어 있다.
장치 획득 시각과 실험 시각의 정밀 동기화는 아직 검증되지 않았다.
별도의 fixation 검출 알고리즘을 적용한 결과도 아니다.

따라서 “관측된 태블릿 시간 + 추적 손실/누락/불확실 시간”을 함께 보고해야 한다.
어느 위치든 추적이 사라지면, 그 시간이 태블릿 주시였는지는 알 수 없다.

## 오프라인 프로필 재생성

장비 위치를 새로 검사한 뒤 해당 검사 폴더에서 새 이름으로 생성할 수 있다.
기존 프로필을 자동 덮어쓰지 않으며, 생성 후 독립 검사와 설정 파일의 경로 변경이 필요하다.

```powershell
.\.venv\Scripts\python.exe -B -m tools.tobii.build_tablet_profile data/gaze_recheck/<새 검사 폴더> --output config/p8_external_tablet_new.json
```

새 파일 경로는 `config/p8_gaze.json`의 `tablet_profile`에 **설정 파일 기준 상대 경로**로 지정한다.
이 도구는 Nano 설정·보정값·원본 검사 파일을 수정하지 않는다.
