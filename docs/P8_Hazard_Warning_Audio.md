# 위험사건 경고음과 훈련 안내

`run_pilot.cmd`의 M2 위험사건 설정을 사용하는 실행에 적용한다.

## 실행 흐름

1. M1·M2 배정 후 `경고음 익히기` 화면에서 짧은 3회 경고음을 자동 재생한다.
2. 피험자는 전방 위험 경고라는 의미를 확인한다. `R`로 다시 들을 수 있다.
3. 경고음 재생 요청 후 약 0.68초가 지나면 `SPACE`로 기존 훈련 주행을 시작한다.
   재생 실패 시에도 화면 안내를 확인하고 계속 진행할 수 있다.
4. M2 위험사건 경고가 화면에 처음 표시된 직후 동일한 경고음을 한 번 재생한다.
   NoA 상태에서는 기존 인수 요청 문구가 함께 표시된다.

훈련 주행 시간 600초는 이 안내 이후 시작한다. 안내 화면에서의 R·SPACE는
훈련 시작을 위한 입력이며, 주행 중 키·핸들·페달 입력 처리는 변경하지 않는다.
실제 경고음으로 자동 제동, 자동 조향, NoA 해제를 수행하지 않는다.
기존 장애물 충돌 안내 후 SPACE 저장·종료 동작도 유지한다.

## 저장 정보

- `research_events_<run-id>.csv`의 `training_warning_audio_play_requested`,
  `training_warning_audio_acknowledged`, `training_warning_audio_closed`:
  최초 재생/재청취, SPACE 확인, 종료 및 오류 정보.
- `m2_hazard_warning_displayed` 이벤트의 `audio`:
  경고음 식별자 `hazard-three-beeps-v1`, 요청 성공 여부, 요청 전후 PC QPC 시각,
  실패 이유. 기존 화면 flip 시각은 그대로 보존한다.
- 세션의 위험사건 기록 `warning_audio`:
  준비 상태, mixer 형식, 시도 횟수, 종료 상태, 오류 목록.
- `collection/hazard_response_metrics.json`의 `warning.audio`에도 같은 재생
  요청 결과를 남긴다. 위 파일들은 기존 결과 ZIP에 포함된다.

`PLAY_REQUEST_ACCEPTED`는 SDL이 재생 요청을 수락했다는 뜻이다. 음소거,
스피커 연결, 실제 청취 여부나 스피커에서 소리가 나온 물리적 시각을
확인한 것은 아니다. 반응시간 기준은 기존 장애물 화면 노출 후보 시각이다.

## 실패 격리와 검증

PCM은 준비 단계에서 만들고, 화면 루프에서는 이미 준비된 짧은 소리만 요청한다.
사용 가능한 비예약 채널을 사용하며 기존 엔진음·깜빡이 채널을 강제로 빼앗지 않는다.
장치 초기화·음원 생성·재생·정리 오류는 기록하고 화면 경고와 주행을 유지한다.
추가한 훈련 안내 로그 쓰기 오류 역시 훈련을 막지 않는다.

오프라인 테스트는 CARLA 서버와 실제 핸들 접근을 금지한 상태에서 실행한다.
실기기에서는 훈련 화면에서 소리가 들리는지, R 재청취와 SPACE 진행,
M2 경고 문구와 한 번의 경고음, 기존 입력·NoA 해제·충돌 종료 흐름을 확인한다.
음량은 장비의 기존 설정을 사용하며 OS 볼륨을 자동 변경하지 않는다.
