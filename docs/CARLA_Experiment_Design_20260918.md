## 1. 연구 목적과 비교 구조 [원본 p.1]

기존 필드 자료만으로 직접 관찰하기 어려운 (1) 실제 자동화 활성화 선택, (2) 운전 중 주의배분, (3) 위험상황에서의 개입 과정을 두 모듈로 분리해 검정한다.

- **Module 1 — Automation Choice:** 이차과제 요구(SuRT)가 가용한 NoA-like L2의 *자발적 활성화 선택*을 늘리는가?
- **Module 2 — Attention & Hazard Response:** 연구자가 배정한 NoA-like L2 사용 상태가 *자연스러운 주의배분*과 *위험대응 성과*를 바꾸는가?
- 이 두 질문을 하나의 실험조건이나 하나의 결과변수로 합치지 않는다. Module 1은 **선택이 결과**, Module 2는 **자동화 상태가 배정된 조건**이다.

### 참가자와 배정

- 면허를 가진 운전자 **약 200명**이 **두 모듈 모두** 수행한다. 총 400명의 별도 참가자가 아니다.
- 모든 참가자의 진행 순서: **훈련/보정 → Module 1 → 짧은 휴식 → Module 2 → 마지막 위험사건 → 사후 설문**.
- 모듈 간 순서는 고정: **Module 1 → Module 2**.
- 모듈 **내** 조건은 각각 100명 대 100명으로 무작위 배정하는 between-subjects 설계이다.
- Module 1의 조건: **SuRT 요구 없음** / **SuRT 요구 있음**.
- Module 2의 조건: **수동주행** / **NoA-like L2 주행**.
- Module 1과 Module 2의 배정 결과를 어떻게 교차 균형화할지는 원본에 명시되어 있지 않다. 임의 확정하지 않는다.

## 2. 공통 시뮬레이션 시스템 [원본 pp.1–2]

자동화 조건은 실제 NoA를 최대한 대응시키려는 **NoA-like Level 2 한 종류**로 단순화한다.

필요한 기능:
1. 자동화된 도로 주행: 차로유지 및 속도제어.
2. 경로상 차로변경이 필요할 때 시스템이 변경을 추천.
3. 운전자가 차로변경 추천을 **확인 또는 거부** 가능.
4. 수동주행에서는 운전자가 모든 운전을 직접 수행.
5. 수동주행과 NoA 조건의 차량 모델과 도로환경은 동일.
6. 실제 제어 상태와 활성화/해제 입력을 구분해 기록할 수 있어야 함.

> 기존 CARLA AUTOPILOT 토글만으로 NoA-like L2의 모든 요구사항을 만족한다고 간주하지 말 것. 현재 코드에서 기능별로 확인해야 한다.

## 3. Module 1 — Secondary-task demand → Voluntary NoA use [원본 p.2]

### 실험 조건과 절차

- 주행시간: **10분** 목표.
- 두 조건 모두 동일한 고속도로 구간을 주행.
- 출발 시 NoA-like 자동화 기능은 **OFF**.
- 운전자는 주행 중 언제든 자동화를 **자유롭게 ON/OFF** 가능.
- **SuRT 없음(100명)** vs **SuRT 있음(100명)**.
- SuRT는 물리적 태블릿에서 표적을 찾아 터치하는 **능동적 이차과제**. 원본의 ‘풍선 터뜨리기’는 구현 예시이지 확정된 화면 설계가 아니다.
- SuRT는 자동화를 켜지 않아도 수행 가능한 쉬운 수준. 운전이 항상 우선이며 언제든 중단 가능하다고 중립적으로 안내.
- SuRT의 수행 여부나 정답 수에 따른 성과 보너스를 두지 않으며 기본 참가비는 과제 수행·자동화 활성화와 무관.

### H1 및 결과변수

H1: *Secondary-task demand increases voluntary use of available driving automation.*

- 활성화 여부 (0/1)
- 첫 활성화까지 시간
- 전체 주행시간 중 자동화 상태 시간 비율
- 활성화 횟수
- 자발적 해제와 재활성화 패턴

문서에 기재된 분석 방향: 활성화 여부는 로지스틱 모형, 활성화까지 시간은 적절한 time-to-event 모형.

## 4. Module 2 — Randomized NoA use → Natural attention allocation [원본 pp.2–3]

### 실험 조건과 절차

- 주행시간: **13분** 목표 (마지막 위험평가 4분은 운영표에서 별도 구간).
- **수동주행(100명)** vs **NoA-like L2 주행(100명)**을 연구자가 무작위 배정.
- 참가자에게 주의분산 수행 과제를 강제하지 않는다.
- 두 조건 모두 운전 **화면 밖의 물리적 태블릿**에 동일한 짧고 중립적인 **일반 동영상**을 제시한다.
- 동영상 시청이나 반응은 요구하지 않는다. 동일한 수동적 비운전 시각 자극이 있을 때 자발적인 시선 이동을 관찰한다.
- SuRT(Module 1의 능동적 과제)와 Module 2의 passive video를 혼동하지 않는다.

### Eye-tracking 확인적 주 결과군

관심 대상 AOI (Area of Interest):
- 전방 도로
- 룸미러
- 좌측 사이드미러
- 우측 사이드미러
- 외부 태블릿
- 기타/분류 불가 영역 (데이터 분류상 필요; 실제 분류체계는 장비/분석 사양 확인 필요)

문서에 기재된 측정 예:
- 전방 도로 응시 비율; 전방 재응시까지 시간; 연속 전방 주시시간.
- 총 off-road gaze time.
- 룸미러 및 좌우 사이드미러 확인 빈도/비율; 차로변경 전 목표측 확인.
- passive-video 구간 태블릿 dwell, first-look latency, 동영상 구간 전방/미러 gaze.

**실험 중 전방 화면, 미러, 외부 태블릿 AOI가 실제 장비에서 안정적으로 분리되는지 파일럿에서 검증한다.** 차량 카메라 화면에 미러를 구현했다는 사실만으로 Eye-tracker 분류 성공을 보장하지 않는다.

## 5. 마지막 위험사건 — 별도 결과군 [원본 p.3]

- **참가자당 마지막 위험사건을 1회** 제시한다.
- 위험사건은 동일한 차량 상태와 상대차 조건에서 발동한다.
- 참가자의 시선 이탈이나 행동에 따라 사건 발생을 선택적으로 조정하지 않는다.
- 결과: reaction time, steering/brake intervention latency, lane keeping, speed control, minimum TTC, 안전경계 침범, 자동 구조 여부.
- 성공적으로 개입한 참가자만 선별하지 않고 **전체 배정 참가자를 분석 분모로 유지**.
- 주의배분과 위험대응은 **서로 별개의 outcome family**. 주의 변화가 위험대응 변화의 필수 매개라고 가정하지 않는다.
- **위험사건의 구체적인 상황, 행위 주체, 정확한 위치·타이밍·임계값은 원본에 명시되지 않았으므로 TBD.** 임의 구현하지 않는다.

## 9. 개발 운영 원칙 (원본에서 파생한 관리 제안)

다음은 실험설계 원문의 직접 인용이 아닌, 구현 과정에서 요구사항을 보존하기 위한 개발 운영 제안이다.

- Phase 0에서 현재 HEAD를 **read-only**로 점검하고, 각 요구사항을 `Implemented / Partial / Missing / Unverified`로 분류한다. 반드시 실제 소스 위치를 근거로 한다.
- Phase 0에는 파일 생성/수정, Git 변경, 새 기능 구현을 포함하지 않는다. 이 명세서는 사용자가 제공하는 **외부 참고 문서**로 먼저 읽을 수 있다.
- Phase 1부터 변경 범위를 승인받고 진행한다. 원본 PDF의 설계나 참가자 조건을 개발 편의상 바꾸지 않는다.
- 로그는 실험 시작/종료와 이벤트를 공통 시간축으로 결합할 수 있어야 한다. 이벤트 명칭·스키마는 현재 코드 조사 후 확정한다.
- 코드 검증과 실물 실험기기 검증은 구분한다. CARLA 단독 테스트로 Eye-tracking/태블릿 통합 완료라고 보고하지 않는다.
- 실제 인간 참가자 모집 및 연구 데이터 수집은 IRB 승인 이후 수행한다.
