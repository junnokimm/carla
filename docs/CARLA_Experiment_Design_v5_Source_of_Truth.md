## 1. 실험 전체 구조

### 1.1 참가자 및 모듈 구조

- 같은 참가자 약 200명이 1회 방문으로 참여한다.
- 모듈 순서는 고정이다.
  1. Module 1
  2. 2분 휴식
  3. Module 2
- 각 모듈 안의 두 조건은 각각 1:1 무작위 배정한다.
- Module 1 배정과 Module 2 배정은 서로 독립이다.
- Module 1의 배정 조건이나 실제 NoA 사용 여부로 Module 2 조건을 정하지 않는다.

### 1.2 Module 1 — 자동화 선택

- 계획 시간: **600초(10분)**
- 무작위 조건:
  - SuRT 없음
  - SuRT 있음
- 목표 배정: 약 100명씩
- 참가자는 같은 고속도로를 주행한다.
- NoA형 기능은 **시작 시 OFF**다.
- 참가자는 주행 중 NoA형 기능을 언제든 켜거나 끌 수 있다.
- SuRT 조건 참가자는 운전과 동시에 태블릿 과제를 수행한다.
- 주 지표:
  - 600초 중 실제 자동화 ON 시간 비율
- 핵심 보조 지표:
  - NoA ON 횟수
  - 해제와 재활성화
  - 자동화 모드에서 차선 변경 추천 대응

### 1.3 Module 2 — 주의배분과 위험대응

- 계획 시간: **13분 + 마지막 위험사건**
- 무작위 조건:
  - 수동
  - NoA형
- 목표 배정: 약 100명씩
- 참가자는 배정된 모드로 같은 고속도로를 주행한다.
- 태블릿에는 중립 영상이 재생된다.
- 참가자에게 영상 시청을 요구하지 않는다.
- 마지막에 사전 비공개 위험사건이 1회 발생한다.
- 주 지표:
  - 사전 정의 AOI에서 유효하게 측정된 시선시간 중 전방 도로 응시 비율
- 핵심 보조 지표:
  - 영상 영역 응시 비율
  - 미러 확인
  - 차선 변경 대응
  - 위험사건 대응

## 2. 참가자 운영 순서

전체 운영 시간은 약 55분이다.

| 순서 | 단계 | 내용 | 계획 시간 |
|---|---|---|---:|
| 1 | 동의·자격 확인 | 설명문, 서면동의, 운전면허·운전경험, 시력과 안경/렌즈, 멀미 이력 확인 | 5분 |
| 2 | 훈련 | 수동 주행 약 3분, NoA형 약 3분, SuRT 약 3분. 참가자가 필요한 조작을 설명 없이 스스로 할 수 있을 때 종료. 위험사건은 연습하지 않음 | 10분 |
| 3 | 시선추적 보정 | 전방, 미러, 태블릿(영상 영역) 보정과 AOI 확인 | 5분 |
| 4 | Module 1 | SuRT 없음/있음, NoA형 자유 선택, 고속도로 진출 1회 | 10분 |
| 5 | 휴식 | 짧은 휴식 및 Module 2 안내 문구 낭독 | 2분 |
| 6 | Module 2 | 수동/NoA형, 주의배분 측정, 고속도로 진출 1회 | 13분 |
| 7 | 마지막 위험사건 | 사전 비공개 장애물 사건 1회와 상태 확인 | 5분 |
| 8 | 사후 절차 | TOAST 9문항, 작업부하 3문항(모듈별), 영상 요리 자유회상 및 목록 선택, 사후설명, 자료이용 동의/거절, 보상 안내 | 5분 |

### 구현 확인 기준

- 두 모듈, 휴식, 위험사건, 설문이 하나의 프로그램 흐름에서 이어져야 한다.
- 각 단계의 시작 시각과 종료 시각이 로그에 남아야 한다.

## 3. 배정 및 운영 규칙

### 3.1 사전 배정표

배정표는 첫 참가자 전에 미리 생성한다.

진행자가 다음 배정을 임의로 고를 수 없게 관리한다.

필수 항목:

| 항목 | 값 및 규칙 |
|---|---|
| `m1_condition` | SuRT 없음 / 있음, 1:1 블록 무작위, 목표 100:100 |
| `m2_condition` | 수동 / NoA형, 1:1 블록 무작위, `m1_condition`과 독립 |
| `participant_id` | 개인정보에서 유도하지 않는 연구용 일련번호. 모든 로그 파일의 연결 키 |

### 3.2 진행자 규칙

- 모든 참가자에게 같은 절차와 같은 문구로 안내한다.
- 조건마다 추가 설명의 길이와 내용이 달라지지 않게 한다.
- 참가자에게 태블릿을 보라고 유도하지 않는다.
- 참가자에게 자동화를 켜라고 유도하지 않는다.
- 반응 속도에 대한 피드백을 주지 않는다.
- 특정 조건이 과제 수행에 유리하다고 암시하지 않는다.
- 참가비는 과제 성과나 자동화 사용 여부와 무관하게 지급한다.
- 참가자가 중단을 요청하면 즉시 멈추고 종료 상태와 부분 자료를 저장한다.

### 3.3 훈련

- 수동 주행: 약 3분
- NoA형 조작: 약 3분
- SuRT: 약 3분
- 참가자가 다음을 진행자 설명 없이 스스로 수행할 수 있을 때 훈련을 끝낸다.
  - NoA형 켜기
  - NoA형 끄기
  - 브레이크로 NoA형이 해제된 뒤 다시 켜기
  - 진출 추천 확인
  - 진출 추천 거부
- 훈련 중 진출 안내를 1회 연습한다.
- 위험사건은 훈련하지 않는다.
- 광운대 연구실의 기존 훈련 절차를 기본으로 한다.
- 운전 경험이 적은 참가자가 10분 안에 익히지 못하면 파일럿에서 훈련 시간을 늘린다.

## 4. 참가자 안내 문구

### 4.1 Module 1 시작 전

> 운전과 주변 확인을 우선해 주세요. 이 구간에서는 주행보조 기능을 원하면 켜거나 끌 수 있습니다. 주행 중 고속도로를 빠져나가야 하는 구간이 한 번 있으며, 내비게이션이 미리 안내합니다. 과제가 제공되면 운전에 지장이 없는 범위에서 수행하고, 필요하면 언제든 멈출 수 있습니다.

### 4.2 Module 2 시작 전

> 이번 구간에서도 도로와 주변 교통을 살피고 필요한 경우 직접 조작해 주세요. 이번 구간에는 태블릿 과제가 없습니다. 태블릿에는 영상이 재생되지만 시청하거나 반응할 필요는 없습니다. 이번에도 고속도로를 빠져나가야 하는 구간이 한 번 있으며 내비게이션이 미리 안내합니다. 안내와 주행 상황에 따라 안전하게 운전해 주세요.

### 4.3 NoA형 조건 공통

- NoA형 기능은 운전자 보조기능임을 안내한다.
- 모든 조건에서 운전과 주변 감시가 우선임을 안내한다.
- 필요 시 직접 개입해야 한다는 감독 책임 안내에 한정한다.
- 장애물, 급제동, 돌발 상황을 암시하는 문구는 넣지 않는다.

### 4.4 사후 인터뷰

1단계 자유회상:

> 영상에서 어떤 요리를 만들었는지 기억나시나요?

- 기억나지 않거나 보지 않았다고 답해도 된다.

2단계 인지:

- 영상의 10가지 요리와 허위 항목 몇 개가 포함된 인터뷰 카드를 제시한다.

> 이 중 영상에서 본 것을 모두 골라 주세요.

기록 항목:

- 자유회상 개수
- 정답 선택 수
- 허위 선택 수

### 4.5 사후설명과 자료이용 확인

- 측정과 사후설문 직후 사후설명문을 설명하고 질문에 답한다.
- 자료이용 동의 또는 거절을 기록한다.
- 자료이용 거절 자료는 분석에서 제외하고 삭제한다.
- 자료이용 거절 여부와 관계없이 보상은 감액하지 않는다.
- 동의/거절 기록 시각을 세션 기록에 남긴다.

## 5. 공통 도로 및 도로 난이도

### 5.1 공통 도로

- 두 모듈 모두 **3차로 고속도로**다.
- 광운대 연구실이 기존 실험에 사용하던 도로를 기본으로 한다.
- 긴 직선 주로 중심이다.
- 다음 요소는 조건에 관계없이 같게 유지한다.
  - 차량
  - 도로
  - 교통
  - 경로 안내
  - 목표 속도
- Module 1:
  - 계획 600초
  - 파일럿에서 짧다고 판단되면 연장 가능
- Module 2:
  - 계획 13분
  - 훈련, 보정, 일시정지, 마지막 위험사건 제외

### 5.2 도로 난이도

- Module 1 전체 600초를 하나의 도로 난이도로 운영한다.
- 쉬움/어려움 구간으로 나누지 않는다.
- 제시 순서 배정을 두지 않는다.

파일럿에서 SuRT 집단조차 NoA형을 거의 켜지 않는 등 자동화를 켤 동인이 약하다고 판단되는 경우:

- 주변 교통 밀도만 높이는 방식으로 조정한다.
- 도로 곡률이나 선형은 변경하지 않는다.

교통 밀도:

- 기본 밀도와 조정 시 밀도는 광운대가 결정한다.
- 두 조건과 두 모듈에 같게 적용한다.
- 시나리오 버전에 기록한다.
- 교통 밀도 설정값과 시나리오 버전을 배정 파일에 기록한다.

## 6. NoA형 L2 기능

### 6.1 기능 범위

NoA형 기능은 다음으로 구성한다.

- 차로유지
- 속도제어
- 운전자 확인을 거치는 차로변경 추천

차로변경 추천:

- 각 모듈의 고속도로 진출 상황 1회에서만 발생한다.
- 운전자 확인이 없으면 아무 일도 일어나지 않는다.
- 운전자가 확인하면 시스템이 차로를 변경한다.

### 6.2 감독 및 운전자 우선권

- 두 조건 모두 hands-on 감독을 전제로 한다.
- 운전자의 제동과 조향이 시스템보다 우선한다.

### 6.3 NoA 활성화

Module 1:

- 시작 시 OFF
- 참가자가 언제든 켤 수 있다.
- 켜기 입력은 핸들 옆 버튼 하나 또는 레버로 지정한다.
- 정확한 버튼은 광운대가 결정한다.

활성화 가능 조건:

- 차량이 차로 중앙에 얼추 정렬되어 있으면 즉시 ON
- 차로에 걸쳐 있거나 차로변경 중이면 ON되지 않음
- 활성화 실패 사유를 로그에 남김
- 해당 조건은 훈련에서 안내함

Module 2 NoA형 조건:

- 시작부터 ON

### 6.4 NoA 해제

- 브레이크를 밟으면 자동 해제된다.
- 버튼으로도 끌 수 있도록 할 수 있다.
- 브레이크 자동 해제와 버튼 해제는 로그에서 사유를 구분한다.
- 버튼 해제와 브레이크 해제를 둘 다 사용할지, 하나만 사용할지는 광운대가 결정한다.

### 6.5 재활성화

- NoA 해제 뒤 언제든 다시 켤 수 있다.
- 재활성화 조건은 최초 활성화 조건과 같다.
- 횟수 제한은 없다.

### 6.6 가용 조건

- NoA형 기능을 켤 수 있는 조건은 모든 조건과 순서에서 같게 유지한다.

### 6.7 위험사건 중 NoA

- 장애물에 대한 충돌 경고를 제공하지 않는다.
- 자동 회피 제동을 제공하지 않는다.
- 평상시 차로 지원과 속도 지원은 유지한다.

## 7. 고속도로 진출 및 차로변경

### 7.1 공통 구조

- 각 모듈에 고속도로 진출 상황을 1회 구현한다.
- 참가자에게 시작 전 한 번의 진출 구간이 있고 알림이 미리 제공된다고 안내한다.
- 두 조건은 같은 위치에서 같은 안내를 받는다.

### 7.2 Module 1

고속도로 진출 안내 시점의 실제 NoA 상태에 따라 처리한다.

NoA ON:

- 추천과 확인 방식

NoA OFF:

- 일반 내비게이션 안내
- 참가자가 직접 운전

안내 시점의 실제 NoA 상태를 로그에 남긴다.

### 7.3 Module 2

NoA형 조건:

- 추천을 확인해야 시스템이 차로를 변경한다.

수동 조건:

- 안내만 받고 참가자가 직접 운전한다.

### 7.4 진출 위치

- Module 1: 600초 후반부
  - 예: 7~8분 지점
- Module 2: 13분의 중후반
- Module 2 진출은 마지막 위험사건보다 충분히 앞에 둔다.
- 정확한 지점은 광운대가 결정한다.
- 조건 간 위치는 동일해야 한다.

### 7.5 사전 내비게이션 안내

- 진출 지점 약 1 km 전부터 화면에 내비게이션 형태로 안내한다.
- 안내 예:
  - `N km 앞 출구, 우측 차로로`
- 수동과 NoA형 모두 같은 안내를 받는다.

### 7.6 NoA형 진출 처리

적용 대상:

- Module 2 NoA형 조건
- Module 1에서 진출 안내 시점에 NoA가 켜져 있는 경우

화면:

- 화살표
- 확인/거부 표시

확인:

- 깜빡이를 켜거나 지정 버튼을 누르는 방식 중 하나를 사용한다.
- 정확한 확인 입력 방식은 광운대가 결정한다.
- 확인되면 시스템이 차로를 변경한다.

거부 또는 무응답:

- 차로변경을 수행하지 않는다.
- 기존 차로를 유지한다.
- 출구를 지나친다.

### 7.7 수동 진출 처리

적용 대상:

- Module 2 수동 조건
- Module 1에서 진출 안내 시점에 NoA가 꺼져 있는 경우

동작:

- 동일한 내비게이션 안내만 제공한다.
- 참가자가 직접 깜빡이와 조향으로 차로를 변경한다.
- 차로를 변경하지 않으면 출구를 지나친다.

### 7.8 진출 이후

- 진출 뒤에도 주행이 끊기지 않아야 한다.
- 같은 고속도로로 이어지거나 짧은 연결로를 거쳐 계속 주행한다.
- Module 2는 이후 위험사건까지 이어진다.
- 정확한 구성은 광운대가 결정한다.

### 7.9 차로변경 필수 로그

- `lc_event_id`
- `module`
- 안내 표시 시각 `t0`
- `noa_state_t0`
- NoA형:
  - 확인 / 거부 / 무응답
  - 해당 시각
- 수동:
  - 변경 / 미변경
  - 깜빡이 시각
  - 조향 시작 시각
- 횡방향 이동 시작 시각
- 차선 통과 시각 `tL`
- 출구 통과 여부

## 8. 마지막 위험사건

### 8.1 형태

- Module 2 마지막에 1회 발생한다.
- 선행차가 비켜나면서 전방의 정지한 무생물 적재물이 드러난다.

### 8.2 발동

- 사전에 정한 시나리오 규칙으로 발동한다.
- 위치와 시각을 기준으로 한다.
- 시선 상태에 따라 발동하지 않는다.

### 8.3 조건 간 동일성

- 장애물 종류는 두 조건에서 같게 한다.

### 8.4 경고 및 자동 제동

다음은 제공하지 않는다.

- TOR
- 충돌 경고
- 자동 회피 제동

### 8.5 자동 구조

- 충돌 또는 도로이탈 경계에 이르면 자동 정지/종료한다.
- 정확한 경계는 테스트 후 확정한다.

### 8.6 비공개 원칙

참가자에게 사전에 다음을 알리지 않는다.

- 위험사건의 존재
- 형태
- 횟수
- 시점

## 9. 태블릿

### 9.1 위치

- 태블릿은 아이트래커 추적 범위 안쪽에 둔다.
- 운전 화면 모니터 오른쪽 아래 모서리에 인접하게 둔다.
- Module 1 SuRT와 Module 2 영상에서 같은 위치를 사용한다.
- 미러 AOI와 겹치지 않게 분리한다.
- 1차 방문에서 태블릿 응시가 독립 AOI인 영상 영역으로 실제 분류되는지 확인한 뒤 위치를 확정한다.
- 좌석, 태블릿 위치, 각도를 사진 또는 치수표로 기록한다.
- 모든 참가자에게 동일하게 적용한다.

### 9.2 Module 1 SuRT

SuRT 조건:

- 여러 원 중 크기가 다른 원을 찾아 터치한다.
- 단일 난이도로 600초 내내 고정한다.
- 자극 크기, 개수, 대비, 제시 규칙을 모든 SuRT 참가자에게 동일하게 적용한다.
- 수동 주행으로 수행 가능한 수준이어야 한다.
- 참가자는 언제든 과제를 멈출 수 있다.
- 성과 피드백을 제공하지 않는다.
- 성과에 따른 보너스를 제공하지 않는다.
- 세부 파라미터는 테스트 후 확정한다.

SuRT 없음 조건:

- 같은 위치의 태블릿을 비활성 화면으로 유지한다.
- 알림이나 다른 과제를 제공하지 않는다.

### 9.3 Module 2 영상

- 두 조건에서 동일한 영상 하나를 사용한다.
- 운전과 무관하고 자극적이지 않은 요리 영상이다.
- 후보:
  - 간단 요리 10가지가 약 1~2분 간격으로 이어지는 약 14분 영상
- 오프라인 파일로 저장해 재생한다.
- 광고와 추천 영상이 노출되지 않게 한다.
- 무음으로 재생한다.
- 참가자에게 시청, 반응, 암기를 요구하지 않는다.
- 사후에 기억을 질문한다는 사실도 사전에 알리지 않는다.
- 위험사건 직전에 끝나지 않도록 13분 이상의 길이를 사용한다.
- 최종 영상 파일은 파일럿에서 확인한다.
- 무음 조건은 고정이다.

후보 영상에 제시된 요리:

- 스팸계란밥
- 참치비빔국수
- 팽이버섯덮밥
- 케첩계란밥
- 메추리알 장조림
- 참치치즈밥
- 간장반숙계란밥
- 콩나물밥
- 계란순두부국
- 계란찜밥

### 9.4 태블릿 로그

SuRT:

- 자극 ID
- 표시 시각
- 터치 시각
- 정오답
- 무응답
- 중단 시각
- 재개 시각

Module 2 영상:

- 재생 시작 시각
- 재생 종료 시각

모든 시각은 공통 시각 기준으로 연결한다.

## 10. 시선 측정

### 10.1 AOI

필수 AOI:

| AOI | 정의 / 배치 조건 |
|---|---|
| 전방 도로 | 운전 화면의 도로 영역 |
| 룸미러 | 화면 안의 룸미러 영역, 추적 범위 안쪽 |
| 좌측 미러 | 화면 안의 좌측 사이드미러 영역, 추적 범위 안쪽 |
| 우측 미러 | 화면 안의 우측 사이드미러 영역, 추적 범위 안쪽 |
| 영상 영역(태블릿) | 추적 범위 안의 태블릿 화면. Module 1에서는 SuRT 화면 |
| 기타 | 유효하게 추적되었지만 위 영역에 속하지 않는 사전 정의 AOI |

- 모든 AOI는 아이트래커 추적 범위 안에 둔다.
- 미러와 영상 영역은 너무 작게 잡지 않는다.
- 영상 영역은 미러 AOI와 분리한다.
- AOI 경계 좌표는 내부 테스트에서 확정한다.
- AOI 파일에는 버전을 표시한다.
- Module 1과 Module 2는 같은 AOI 정의와 같은 유효성 기준을 사용한다.
- Module 1 시선은 선택 대 배정 보조 분석에 사용한다.

### 10.2 시선 상태 처리

전방 도로 응시:

- 전방주시 시간
- Module 2 주 지표의 분자

미러 응시:

- 운전 관련 주변 확인 시간
- 유효 시선시간 분모에 포함

영상 영역 응시:

- 비운전 자극으로 향한 시선
- 핵심 보조 지표의 분자
- 유효 시선시간 분모에 포함

기타 AOI:

- 분모에 포함
- 사전 정의 AOI에 속하지 않는 샘플을 `기타`로 넣지 않는다.

다음은 모두 결측으로 처리하고 분모에서 제외한다.

- 추적 범위 밖으로 튄 샘플
- 사전 정의 AOI 밖의 샘플
- 눈 깜빡임
- 계측 실패
- 방향 판정 불가

어느 영역으로도 대체하지 않는다.

### 10.3 전방주시 비율

`전방주시 비율 = 전방 도로 응시시간 ÷ 사전 정의 AOI에서 유효하게 측정된 시선시간`

분모:

- 전방 도로
- 미러
- 영상 영역(태블릿)
- 기타 사전 정의 AOI

- 어느 AOI에도 속하지 않는 샘플은 분모에 넣지 않는다.
- 영상 영역 응시 비율도 같은 분모를 사용한다.
- 추적 범위 밖 샘플은 분모에서 제외한다.

Module 2 관찰 구간:

- 계획된 13분 중
  - 훈련 제외
  - 보정 제외
  - 일시정지 제외
  - 마지막 위험사건 제외

### 10.4 미러 확인 사건

- 같은 AOI에서 **150ms 이상 지속된 유효 응시**를 미러 확인 사건으로 센다.
- 결측 구간을 이어 붙여 150ms를 채우지 않는다.
- 추적 범위 밖으로 나갔다가 다시 들어온 시선은 다시 들어온 시점부터 정상 분류한다.

### 10.5 시선 품질 기준

참가자별 유효 시선 비율:

`추적 범위 안 유효 시선시간 ÷ 관찰 구간`

- 이 값이 내부 테스트에서 정한 하한보다 낮으면 Module 2 주 지표를 결측 처리한다.
- Module 1 결과와 차량 로그는 유지한다.
- 정확한 하한은 테스트 후 확정한다.

참가자별 기록:

- 안경/콘택트렌즈 착용 여부
  - 없음
  - 안경
  - 렌즈
- 보정 성공 여부
- 유효 시선 비율

안경/렌즈 착용 여부와 보정 결과는 선정 또는 제외 기준이 아니다.

### 10.6 시선 보정

- 전방
- 미러
- 태블릿(영상 영역)

진행자가 영역 이름을 말하면 참가자가 해당 영역을 응시하게 하여 AOI와 대조한다.

안경 및 렌즈 착용자는 특히 확인한다.

### 10.7 원본 영상

- 시선추적 장비가 기록하는 얼굴 및 눈 원본 영상은 광운대 내부 장치에 보관한다.

## 13. 구현 시 금지하거나 임의로 추가하지 않을 사항

v5 기준으로 다음을 임의로 추가하거나 변경하지 않는다.

- Module 1과 Module 2의 순서를 바꾸지 않는다.
- Module 1 조건을 이용해 Module 2 조건을 결정하지 않는다.
- Module 1을 쉬움/어려움 구간으로 나누지 않는다.
- 자동화 사용을 참가자에게 유도하지 않는다.
- 태블릿 영상을 보라고 요구하지 않는다.
- 반응 속도에 대한 성과 피드백을 제공하지 않는다.
- 위험사건을 사전에 암시하지 않는다.
- 위험사건을 시선 상태에 따라 발동하지 않는다.
- 위험사건에서 TOR를 제공하지 않는다.
- 위험사건에서 충돌 경고를 제공하지 않는다.
- 위험사건에서 자동 회피 제동을 제공하지 않는다.
- NoA 차선변경은 운전자 확인 없이 자동 실행하지 않는다.
- SuRT 없음 조건에서 다른 과제나 알림을 제공하지 않는다.
- 사전 정의 AOI 밖 시선 샘플을 임의로 `기타` AOI에 포함하지 않는다.
- 내부 테스트와 파일럿의 데이터를 본실험 200명 분석 자료에 포함하지 않는다.

# 14. v5 기반 개발 계획

아래 Phase는 **v5 사양을 구현하기 위한 개발 순서**이며, 각 Phase의 기능과 완료 조건은 모두 v5에 명시된 요구사항 또는 구현 확인 항목만을 사용한다.  
여기에 없는 기능이나 수치는 새 실험 요구사항으로 추가하지 않는다.

## Phase V5-1 — 공통 세션 구조, 배정, 공통 시각, 로그 기반

### 목표

모든 실험 단계와 장치 데이터를 하나의 참가자 세션으로 연결할 수 있는 기반을 구현한다.

### 구현 대상

- `participant_id`
- `run_id`
- 사전 생성된 `m1_condition`
- 사전 생성된 `m2_condition`
- `route_id`
- `scenario_version`
- AOI 파일 버전
- 프로그램 버전
- `session_elapsed_s`
- 단계별 시작·종료 기록
- 장치별 원본 시각 보존
- 장치별 시각의 공통 시각 변환값 기록
- 중단 및 부분 저장
- 기존 ID 파일 덮어쓰기 방지
- 실행 직후 실제 파일 값 확인

### 완료 조건

- 모든 파일이 `participant_id`, `run_id`, `session_elapsed_s`로 연결된다.
- 같은 ID로 실행해도 기존 파일을 덮어쓰지 않는다.
- 비정상 종료 또는 연결 끊김 후 저장된 범위와 손실 범위를 확인할 수 있다.
- 실험 단계별 시작 및 종료 시각이 기록된다.

## Phase V5-2 — 공통 도로 및 NoA형 L2 기본 동작

### 목표

두 모듈과 모든 조건에서 동일하게 사용할 공통 도로와 NoA형 L2 기본 기능을 구현한다.

### 구현 대상

- 3차로 고속도로
- 긴 직선 주로 중심
- 조건에 관계없이 동일한 차량, 도로, 교통, 경로 안내, 목표 속도
- 단일 도로 난이도
- 차로유지
- 속도제어
- NoA 활성화
- 차로 중앙 정렬 여부에 따른 활성화 허용/거부
- 활성화 실패 사유 기록
- Module 1 시작 OFF
- Module 2 NoA 조건 시작 ON
- 브레이크 자동 해제
- 버튼 해제를 사용할 경우 해당 해제 사유 구분
- 재활성화
- 운전자 제동과 조향 우선
- 모든 조건에서 동일한 NoA 가용 조건

### 완료 조건

- NoA를 켤 수 있는 상태에서 정상 활성화된다.
- 차로에 걸쳐 있거나 차로변경 중에는 활성화되지 않는다.
- 활성화 실패 사유가 로그에 남는다.
- 브레이크로 NoA가 해제된다.
- 해제 사유가 로그에 남는다.
- 해제 후 다시 활성화할 수 있다.
- Module 1과 Module 2에서 규정된 초기 NoA 상태가 적용된다.

## Phase V5-3 — 각 모듈의 고속도로 진출 및 차로변경

### 목표

Module 1과 Module 2 각각 1회의 고속도로 진출 상황을 구현한다.

### 구현 대상

- 두 조건에서 동일한 진출 위치
- 진출 전 내비게이션 안내
- `N km 앞 출구, 우측 차로로`
- Module 1의 안내 시점 NoA 상태 기록
- NoA ON 시 추천 및 확인
- NoA OFF/수동 시 직접 차로변경
- NoA 확인/거부/무응답 처리
- 확인된 경우에만 시스템 차로변경
- 거부/무응답 시 차로 유지 및 출구 통과
- 수동 시 깜빡이와 직접 조향
- 진출 이후 계속 주행
- `t0`, `tD`, 횡방향 이동 시작 시각, `tL`, 출구 통과 여부 기록

### 완료 조건

- 수동과 NoA형에서 같은 위치에 같은 진출 안내가 나온다.
- NoA형은 확인 없이는 차로를 변경하지 않는다.
- Module 1에서는 안내 시점의 실제 NoA 상태에 따라 처리된다.
- 출구를 지나쳐도 주행이 이어진다.
- `t0`, `tD`, `tL`, 출구 통과 여부가 로그에 기록된다.

## Phase V5-4 — 태블릿 및 SuRT / Module 2 영상

### 목표

Module 1과 Module 2의 태블릿 조건을 v5와 동일하게 구현한다.

### 구현 대상

태블릿 배치:

- 모니터 오른쪽 아래 모서리 인접
- 아이트래커 추적 범위 안쪽
- 미러 AOI와 분리
- 좌석, 위치, 각도 기록
- 모든 참가자에게 동일 적용

Module 1:

- SuRT 조건: 여러 원 중 크기가 다른 원을 찾아 터치
- 600초 단일 난이도
- 참가자 자율 중단 가능
- 성과 피드백 없음
- 보너스 없음
- SuRT 없음 조건: 동일 위치 비활성 화면

Module 2:

- 두 조건에 동일한 요리 영상
- 13분 이상
- 오프라인 재생
- 무음
- 시청/반응/암기 요구 없음
- 위험사건 전에 영상이 끝나지 않음

로그:

- SuRT 자극 및 반응 이벤트
- 영상 시작/종료
- 영상 파일 이름과 버전

### 완료 조건

- SuRT 없음 조건에서 태블릿은 비활성 상태다.
- 두 Module 2 조건에서 같은 영상이 같은 시각부터 재생된다.
- 영상은 위험사건 전 끝나지 않는다.
- SuRT와 영상 이벤트가 공통 시각에 연결된다.

## Phase V5-8 — 내부 테스트, 파일럿, 설정표 고정

### 내부 테스트에서 확인할 항목

1. 시선 유효성 기준
   - 유효 시선 비율 하한
   - 허용 연속 결측
   - AOI 경계
2. 위험사건 시작 상태
   - 목표 속도
   - 최초 가시 거리
   - TTC
   - 자동 구조 경계
   - 수동과 NoA형 비교 가능성
3. 태블릿 및 AOI
   - 모니터 오른쪽 아래 모서리 인접
   - tracking range 안쪽
   - 독립 AOI 분류
   - 범위 밖 후 재추적
   - 손실 및 범위 밖 결측 처리
   - 안경 착용자 반복 확인
4. NoA를 켤 동인이 충분한지 확인
   - SuRT 집단에서도 거의 켜지 않으면 교통 밀도만 높이는 조정 검토
5. SuRT 파라미터
   - 수동 주행 중 수행 가능한 수준인지 확인
6. NoA 조작
   - 켜기 버튼
   - 차로 중앙 조건
   - 브레이크 자동 해제
   - 재활성화
   - 훈련 시간
7. 고속도로 진출
   - 같은 위치 안내
   - 확인 입력
   - NoA 무확인 시 미변경
   - 출구를 지나친 뒤 주행 지속
   - `t0`, `tD`, `tL`, 출구 통과 여부
8. 태블릿 위치와 영상
   - 위치/좌석/각도 기록
   - 요리 영상 후보 확인
9. 시각 동기화
   - 장치 간 시각 차이가 일정한 오프셋인지 드리프트인지 확인
10. 저장 및 원자료 검증
   - 실행 직후 실제 값 존재 확인
   - 원자료에서 결과까지 재계산 가능 여부 확인
11. 전체 55분 절차
   - 내부 테스트에서 네 조건 조합 전체 실행
   - 저장
   - 초기화
   - 복구
   - 사후설명
   - 자료이용 확인 단계

### 파일럿

- 본실험 전 필수 단계다.
- 광운대 연구실 인원 3~5명이 참여한다.
- 본실험과 동일한 절차와 기록으로 수행한다.
- 파일럿 자료는 기능과 절차 확인에만 사용한다.
- 본실험 분석에는 포함하지 않는다.
- 파일럿 후 설정표 v1을 고정한다.

## 16. 표본 및 본실험 데이터 원칙

- 대상:
  - 유효한 운전면허를 가진 성인
  - IRB 접수본의 연령 범위
- 목표:
  - 두 주행 모듈과 마지막 위험사건 절차를 완료한 참가자 200명
- 자격을 충족하고 동의해 등록하는 참가자:
  - 최대 250명
- 두 기준 중 먼저 도달하면 신규 모집을 종료한다.
- 완료 여부는 절차 수행 기준이다.
- 수행 성과나 자료 품질로 완료 여부를 재정의하지 않는다.
- 중간 결과를 보고 모집 기준을 변경하지 않는다.
- 내부 테스트와 파일럿 자료는 본실험 200명 데이터에 포함하지 않는다.
