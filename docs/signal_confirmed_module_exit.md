# 진출 안내 중 깜빡이 확인 방식 (2026-10-20)

`run_pilot.cmd`의 M1·M2 및 훈련에서 사용한다. 2026-10-19에 추가했던
운전자 입력 없는 자동 진출 시작을 제거했다. NoA가 켜졌다는 이유만으로
깜빡이를 켜거나 차로를 옮기지 않는다. NoA 활성화·해제 조건, 핸들·페달 축,
위험사건 동작 및 네이티브 RPC 보호는 유지한다.

## 피험자가 보는 흐름

주행 화면에는 `전방 0.9 km, 오른쪽 출구입니다`처럼 출구 거리와 방향만 표시한다.
`진출하려면 우측 깜빡이를 켜 주세요`, `X 확인 / R 거부`, `NoA 자동 진출` 문구,
별도 확인·거부 키 입력은 사용하지 않는다.
X는 기존 우측 깜빡이 키로 동작하며 핸들 버튼도 같은 입력 경로를 사용한다.

훈련 시작 전 터미널에 조작 안내를 한 번 출력한다. 진행자는 NoA에서 깜빡이
한 번에 인접 차로 한 칸을 이동하고, 여러 차로 이동에는 완료 후 다시 입력하며,
출구 안내에 따라 가장 오른쪽 진출 차로에 도달하면 진출 지원이 이어진다는
사용법을 알려 준다. 주행 중에는 수락·거부를 요구하거나 연구 판정 기준을 표시하지 않는다.

안내가 표시되는 동안 우측 깜빡이를 켜면 진출 의사 입력으로 기록한다.
차선 변경은 기존 일반 NoA 실행기가 처리하므로 입력 한 번당 인접 차로 한 칸을
이동하고 완료 후 자동 소등한다. 안쪽 차로에서는 기존과 같이 필요한 횟수만큼
깜빡이를 조작한다. 마지막 진출 차로에 도달하면 해당 출구 분기를 선택한다.
안내가 끝나기 전에 첫 의사 입력이 있었다면, 이동과 진출은 안내가 끝난 뒤에도
완료할 수 있다. 입력만으로 실제 진출 성공을 기록하지 않는다.

안내가 사라질 때까지 의사 입력이 없으면 NoA 상태의 해당 기회를 `NORESPONSE`로
확정한다. 같은 기회에서 안내를 다시 띄우거나 늦은 입력을 동의로 받아들이지 않는다.
늦은 깜빡이도 일반 차선 변경에는 사용하지만, 해당 출구에서는 본선 직진 경로를
지정하여 임의 출구 선택을 방지한다. NoA가 꺼지면 수동 제어가 우선한다.
진출 동의 뒤 NoA 해제 또는 반대 방향 깜빡이가 있으면 진출 지원을 취소한다.

## 설정표

| 항목 | 현재 값 | 기준 |
|---|---|---|
| 진출 안내 최대 표시 시간 | 15.0초 | 첫 실제 화면 표시(`lc_presented`)부터; 훈련·M1·M2 공통 |
| 의사 입력 인정 기간 | 안내 표시 기간과 동일 | 별도의 보이지 않는 판단 창 없음 |
| 시간 종료 경계 | 시작 + 15초 이상이면 종료 | 이후 입력은 동의로 인정하지 않음 |
| 조기 안내 종료 | 접근 구간 이탈, 모듈 기회 종료, HUD 숨김 | 종료 후 다시 열지 않음 |
| 거리 조건 | 경로상 출구까지 1,000m 이내 및 유효 접근 구간 | 기존 경로 사용 |
| M1 진출 기회 허용 시각 | 모듈 주행 180–600초 | 최소 3분 주행 후 유효 출구 접근 시 표시 |
| M2 진출 기회 허용 시각 | 모듈 주행 100–500초 | 기존 설정 유지 |
| 기회 수 | 모듈별 구성된 기회 1회 | 무응답 후 다음 바퀴에서 재시도하지 않음 |
| 방치된 진출 기회 종료 | 안내 종료 후 알려진 진출 경로 밖에서 2초 연속 관측 | 경로 미일치 및 road/section이 접근·출구·본선 통과 목록 밖일 때만 적용 |
| 종료 증거의 최대 관측 간격 | 1초 | 더 긴 공백·좌표 정보 누락·경로 복귀 시 2초 계수 초기화 |
| M2 위험사건 출현 순서 | M2 진출 기회 경험 및 물리적 종료 후 | 실제 안내 표시 + 진출/본선 통과 관측 또는 위 2초 이탈 확인 필수 |
| M2 위험사건 허용 시각 | 모듈 주행 400–600초 | 기존 예정 시각·앞차 없음·안정 목표 속도 등 준비 조건도 모두 충족해야 함 |
| 진출이 끝나지 않은 경우 | 위험사건 보류, 600초 초과 시 `NOT_OCCURRED` | 순서를 뒤집거나 진출을 강제하지 않고 M2 주행 계속 |

표시 시간은 `config/p8_pilot.json`의 `exit_guidance_duration_s`이며,
`tools/run_pilot.py`가 `--exit-response-timeout-s`로 전달한다. 이전 설정 파일에
이 항목이 없으면 15초를 사용한다. 모듈별 허용 시각도 같은 JSON에 있다.
모듈 허용 구간은 안내가 처음 나타날 수 있는 시간이고, 안내 표시 15초와는 다른 설정이다.
180초 정각에 강제로 안내하지 않으며, 늦게 접근 구간에 들어오거나 구간을 이탈하면
15초보다 짧아질 수 있다. 출구를 지난 뒤까지 시간을 채우려고 안내를 유지하지 않는다.
프레임 단위 화면 갱신이므로 실제 숨김 시각도 별도로 기록한다.

설정과 해당 Python 모듈은 실행 시작 시 읽는다. 이 변경 중 이미 진행 중인
실행은 기존 메모리의 5초·M1 0초 설정과 문구를 계속 사용하며, 다음 `run_pilot.cmd`
실행부터 바뀐다. 실행 중인 세션이나 경로 매니페스트·네이티브 바이너리는 변경하지 않았다.
경로 매니페스트의 개발 기본값 5초는 파일럿 런처의 명시적 15초 설정으로 덮어쓴다.

## 로그

- `p5_exit_manifest`: `exit_policy=INDICATOR_DURING_VISIBLE_GUIDANCE`,
  `guidance_display_duration_s=15.0`, 별도 확인·거부 키는 `null`.
- `lc_presented`: 최초 실제 안내 표시 시각 `t0_host_monotonic_ns`.
- `guidance_deadline_host_monotonic_ns`: 설정상 안내 종료 시각.
- `lc_guidance_closed`: 안내 종료 판정 시각·사유. `lc_guidance_hidden`은 실제
  화면 갱신 후 숨김 시각이며 `guidance_hidden_host_monotonic_ns`에 저장한다.
- `lc_decision`: 입력이 있으면 `CONFIRM`, `decision_source=DRIVER`, 실제
  `input_receipt_host_monotonic_ns`. 입력이 없으면 `NORESPONSE`, `decision_source=NO_INPUT`.
- `lc_late_indicator_ignored_for_exit`: 늦은 우측 깜빡이를 해당 이벤트 시각으로 남긴다.
  동의 시각이나 기존 무응답 결정을 덮어쓰지 않는다.
- `lc_exit_route_submitted` / `lc_through_route_submitted`: 끝차로 진출 또는
  무응답 본선 통과 경로 요청. 완료의 증거로 사용하지 않는다.
- `lc_completed`: 관측된 `EXIT` 또는 `MISSED`. 적시 입력 후 실제 진출이면
  `consent_outcome=SIGNALLED_AND_EXITED`, 입력 후 놓쳤다면 `SIGNALLED_EXIT_NOT_COMPLETED`.
  무응답인데 실제 진출한 예외는 `EXIT_WITHOUT_TIMELY_SIGNAL`로 남기고 결과를
  `INCOMPLETE`로 분류한다. 동의·성공으로 바꾸지 않는다.

새 진출 이벤트의 로그 전달 오류와 경로 요청 오류는 기록하며 주행을 중단하지 않는다.

## M2 진출 선행 보장 (2026-10-20)

`P8_CLEAR_ROAD_EXIT_FIRST_V4`부터 위험사건 준비와 장애물 출현은 **현재 M2에서
안내가 실제 표시되고 해당 진출 기회가 물리적으로 끝난 뒤**에만 가능하다.
진출 성공 `EXIT`, 본선 통과 `MISSED`, 기존의 연속 경로 이탈 확인
`EXIT_CORRIDOR_LEFT`를 구분하여 인정한다. 이탈 확인을 진출 성공으로 바꾸지 않는다.
안내가 사라짐, `NORESPONSE`, 끝차로로 차선 변경 완료, NoA 해제로 지원 취소만으로는
물리적 종료를 인정하지 않는다. M1·훈련에서 경험한 진출도 M2의 선행 경험을
대신하지 않는다. 실제 차선 변경 중이거나 진출 경로 취소가 확인되지 않았으면
종료 증거가 있어도 위험사건을 계속 보류한다.

진출 허용 100–500초와 위험사건 허용 400–600초는 유지한다. 허용 시간대가 겹쳐도
선행 조건으로 실제 발생 순서를 보장하며, 진출 종료 후 앞차 없음·목표 속도 안정
조건을 다시 확인한다. 예정 시각이 지났다면 조건 충족 후 남은 허용 시간 안에
출현한다. 안내 자체를 못 봤거나 진출이 끝나지 않은 채 600초를 넘기면 장애물을
생성하지 않고 `NOT_OCCURRED`와 사유를 남긴다. 모듈 종료 시간을 늘리거나
운전자의 깜빡이·핸들·페달·NoA 해제 동작을 바꾸지 않는다.

`m2_hazard_scheduled`·최종 기록의 `event_order_policy`는
`M2_PRESENTED_AND_PHYSICALLY_RESOLVED_EXIT_BEFORE_HAZARD`다.
`m2_hazard_readiness_evaluated.checks.exit_before_hazard`에 선행 조건의 성공/실패,
M2 진출 이벤트 ID, 표시·종료 시각, 결과·종료 사유를 저장한다.
`m2_hazard_end`·위험사건 최종 기록의 `exit_sequence_at_reveal`에는 출현 시도 직전
증거를 고정해 저장한다. 선행 조건 미충족으로 출현을 시도하지 않았으면 `null`이며,
미충족 이유는 준비 조건 로그에 남는다. 이 필드 자체는 실제 장애물 표시 성공을
뜻하지 않으며, 성공 여부는 기존 `first_geometry`·`display_candidate`로 확인한다.
증거의 시각은 기존 사건과 같은 PC 단조 시각으로 비교할 수 있다.

이번 수정의 관련 오프라인 회귀 검사: 846건 통과, Windows 심볼릭 링크 생성 권한이
필요한 기존 내보내기 검사 1건 건너뜀. 순서 검사 29건과 진출 미표시 상태로 M2를
완료하는 통합 검사 2건을 추가했다. 기존 통합 검사는 실제 진출 조정기의 표시·본선
통과를 먼저 관측하도록 테스트 입력을 보완했다. 진출 이후 충돌 안내·SPACE 확인·
부분 기록·ZIP 저장, 정상 완료, 무응답, 일반 차선 변경·NoA 해제·핸들 입력을 포함한다.
증빙은 `data/exit_first_verification/summary.json`에 있다. 테스트용 ZIP 생성은
샌드박스 파일 이름 변경 제한 때문에 해당 테스트만 제한 밖에서 재검증했으며,
CARLA 연결과 물리 조이스틱 접근은 오프라인 실행기로 계속 금지했다.
실제 언리얼·핸들 주행 검증은 수행하지 않았다.
경로 요청이 실패한 경우에는 출구 선택을 보장하거나 성공했다고 기록하지 않는다.
일반 입력 및 차량·시뮬레이터 장애에 대한 기존 복구 처리도 유지한다.

2026-10-20 진출 상태 잔류 보완: 인접 차선 변경 완료를 출구 진출 완료로
간주하지 않는다. 알려진 접근·출구·본선 구간에서는 적시 동의 후의 진출 지원을
유지하며, 안내 시간 만료만으로 이를 취소하지 않는다. 해당 기회를 벗어난
연속 물리 관측이 확인되면 `lc_opportunity_retired`와
`lc_finished(termination_reason=EXIT_CORRIDOR_LEFT, outcome=INTERRUPTED)`를
남기고 동의를 재사용하지 않는다. 기존 `CONFIRM`/`NORESPONSE`는 보존하고,
확인하지 못한 실제 경로를 `EXIT`나 `MISSED`로 만들지 않는다.

일반 차선 변경은 별도 실행기가 계속 담당한다. 진출 기회를 정리했더라도
실제 차선 변경이 진행 중이면 위험사건은 보류한다. 진출 경로의 취소 요청을
확인하지 못한 경우에도 `P5_EXIT_ROUTE_CANCELLATION_UNVERIFIED`로 보류하며,
이를 성공 처리하지 않는다. 주행·핸들·NoA 해제 처리는 계속 진행한다.

1건 건너뜀**(심볼릭 링크 생성 권한). 실제 NoA/SDL 바이너리를 로드하되
CARLA 접속과 물리 조이스틱 접근은 금지했다. 최초 샌드박스 실행의 ZIP 저장
8건은 파일 이름 변경 권한 제한으로 실패하여 권한이 허용된 환경에서 재실행했고,
8건 모두 통과했다. 결과는 `data/exit_hazard_verification/regression_1.xml`,
`export_unrestricted.xml`, `summary.json`에 있다.

2026-10-20 안내 시점·표시 시간·문구 조정: 오프라인 검사 **194건 통과**.

진행 중인 실험·언리얼을 재시작하거나 실주행 검증을 수행하지 않았다.
