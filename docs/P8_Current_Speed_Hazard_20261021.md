# M2 현재 속도 기반 위험사건과 주행 연장

2026-10-21 사용자 승인에 따른 운영 정책 변경이다. `run_pilot.cmd`의
`ClearRoadM2Hazard`에 적용하며 이전 파일럿 원자료는 변경하지 않는다.
이 문서의 정책이 과거 목표속도 일치·600초 만료·780초 고정 종료 설명을 대체한다.

## 설정과 동작

| 항목 | 적용값 |
|---|---|
| 기준 속도 | 출현 배치 직전 관측한 실제 차량 속도. 도로 제한속도/목표속도 조회·일치 조건 없음 |
| 거리 | `현재 km/h ÷ 3.6 × 4초`. 현재 차로 경로를 따라 차량 전면 외곽과 장애물 후면 외곽 사이의 간격 |
| 극저속 보류 | 10km/h 미만. `MovingHazardConfig.minimum_exposure_speed_kmh` |
| 준비 확인 | 동일 차로에서 10km/h 이상 주행·전방 경로 적합 상태 2초. 가속/감속 및 목표속도와의 차이는 제한하지 않음 |
| 관측 공백 | 0.25초 초과이면 준비 유지 시간 다시 확인 |
| 경로 재검사 | 1초 주기 및 실제 배치 직전 |
| 교차로/불명확한 경로 | 현재 차량 위치부터 4초 거리 및 외곽 여유까지 교차로·분기 불명확 구간이면 보류 |
| 전방 차량 | 장애물까지의 접근 경로가 점유되면 보류. 앞차를 새로 만들지 않음 |
| 배치 가능 여부 | 출현 전 화면 투영과 충돌 경로를 검사. 부적합이면 사건 기회를 소모하지 않고 다음 구간에서 재시도 |
| 진출 선행 | 같은 M2의 진출 안내가 실제 표시되고 그 기회가 물리적으로 종료되어야 함. 진출 완료/지나침/기회 종료 모두 기존 판단 그대로 |
| 차로변경 중 | 기존 진출·일반 NoA 차로변경 및 취소 미확인 상태에서는 계속 보류 |
| 예정 시각 | 기존 seed로 400~600초에서 한 번 추첨. 그 시각 이전에는 노출하지 않음 |
| 600초 이후 | 사건을 만료시키지 않고 같은 기회를 유지 |
| M2 기본 시간 | 780초. 그때 아직 미노출이거나 노출 후 기록 시간이 부족하면 같은 주행을 연장 |
| 노출 후 기록 | 최소 10초 (`post_exposure_drive_s`). 종료는 `max(780초, 최초 표시 후보 시각 + 10초)` 이후. 충돌/관리자 종료는 별도 기존 절차 |
| 중복 방지 | 배치 전 최종 조건 확인 이후 1회 예약. 배치 명령 이후에는 새 장애물로 재시도하지 않음 |

4초는 배치 시 속도와 경로를 유지했을 때의 예상 충돌 시간이다.
제동·조향·가속, CARLA 스냅샷 및 화면 표시 지연 때문에 첫 실제 표시 프레임의 TTC는
정확히 4.000초가 아닐 수 있다. 배치 요청과 관측/표시 프레임의 값을 각각 보존한다.

10km/h·2초·10초는 이번 운영 설정이며 검증된 연구 임계값을 뜻하지 않는다.
기존 `stable_speed_s=2` 필드명은 호환성을 위해 남지만, 현재는 일정 속도 유지가
아닌 적합한 주행·경로 조건의 유지 시간을 의미한다. `target_speed_kmh`와
`speed_tolerance_kmh`는 이전 설정 호환용으로 남고 이 사건의 통과 조건에는 쓰지 않는다.

정지 상태나 부적합 경로가 계속되면 임의로 장애물을 겹쳐 생성하지 않고 계속 기다린다.
이 경우 연장 상한은 없으며 관리자는 기존 ESC로 종료할 수 있다. 진출 선행 조건도
연장 시간 때문에 우회하지 않는다. 기술적 생성/배치 오류로 사건을 무효화한 경우에도
실험 창을 닫지 않고, 연장 시 진행자 확인 안내를 표시하여 종료 결정과 저장 시도를 맡긴다.
실제 Unreal/OS/장치 장애까지 소프트웨어 검증으로 발생을 보장하는 것은 아니다.

## 유지한 기능

주행 제어·핸들/페달 변환·NoA 활성화와 해제 조건·깜빡이 차로변경/진출은 바꾸지 않는다.
자동 회피 제동/조향을 추가하지 않는다. 기존 시각·음향 경고와 NoA 인수 요청,
장애물 충돌 안내 후 SPACE 저장/종료 절차를 유지한다.
연장 중에도 같은 입력·관측·카메라·시선 수집 루프를 계속 실행한다.

## 로그와 ZIP

- 정책: `M2_CURRENT_SPEED_TTC4_EXTEND_V3_20261021`,
  `CLEAR_ROAD_CURRENT_SPEED_TTC4_NO_LEAD`.
- `m2_hazard_scheduled`: `planned_draw_window_s=[400,600]`,
  `window_s=[예정시각,null]`, 연장 정책과 전체 설정.
- `m2_hazard_readiness_evaluated`: `moving_speed_eligible`, 진출 선행·충돌,
  경로·교차로·앞차·카메라·적합 주행 유지 시간. 최종 배치 검사에는 `placement_geometry`도 기록.
  앞 단계에서 중단된 검사는 `NOT_CHECKED`로 남는다.
- `m2_hazard_obstacle_reveal_requested`와 최종 `placement`:
  `placement_speed_kmh`, `requested_bumper_clearance_m`, 차로, 배치 좌표, 목표 TTC.
- `m2_hazard_m2_extension_started/completed`: 기본 시간, 실제 시간, 연장 사유와 기간.
- 위험사건 최종 기록 `duration_extension` 및 모듈 기록 `hazard_extension`:
  연장 완료/도중 종료와 실제 주행 시간을 구분한다.
- 정상 연장 완료는 `completion_reason=HAZARD_EXTENSION_COMPLETE`.
  관측 비율은 실제 모듈 구간을, 기존 nominal 비율은 기본 780초를 분모로 사용한다.
- 사건 반응 집계는 600초/780초 이후의 정상 노출도 같은 기준으로 처리한다.
  시선 집계는 실제 모듈 시작/종료 경계를 사용한다. 연장 정보와 원본 이벤트는 기존 ZIP에 포함한다.

로그 오류는 주행·사건 진행과 분리한다. 원본 입력 배치는 기존 확인/재시도 체계를
유지하되 저장 장애 동안 버퍼를 무한히 늘리지 않는다. 누락 샘플 수를
`raw_storage.dropped_samples_during_storage_failure`에 남기며 원본을 꾸며 채우지 않는다.

## 검증 범위

오프라인 검증은 실제 CARLA 접속과 물리 핸들 사용을 금지한 하네스로 수행한다.
MANUAL/NoA, 4개 차로, 10·30·60·90·120km/h, 가속 중 배치,
정지·극저속·교차로 보류 후 780초 이후 출현, 진출/차로변경 선행 조건,
연장 중 조향·페달·ESC·충돌 확인, 로그 장애와 버퍼 복구,
실제 Runner/Controller 경유 연장 집계 및 ZIP 무결성을 검사한다.

검증 산출물은 `data/current_speed_hazard_verification/`에 저장한다.
실기기에서는 낮은 속도의 MANUAL 주행에서 진출 기회 종료 후 사건 출현,
정지/교차로 대기 중 미출현, 재출발 후 현재 차로 출현, 경고 및 충돌 확인 종료를 확인한다.

최종 집중/통합 검증은 **218건 통과**(168 + 50)했다. 가상 MANUAL·NoA 두 실행 모두
780초에 연장을 시작하고 802.1초에 노출, 812.1초에 종료했다.
각 ZIP CRC가 정상이며 실제 주행 시간·연장 정보·`RESPONSE_OBSERVED` 반응 지표를 확인했다.

전체 회귀는 **2,855건 통과 / 2건 건너뜀 / 6건 실패**이다.
실패는 기존 콕핏/미러 배치 기대값 5건과 이전 AOI 영역 기대값 1건이며,
수정 전 Git HEAD 코드를 메모리에서 불러 실행한 검사에서도 같은 6건이 재현되었다.
실제 화면 배치와 AOI 설정은 이번 작업에서 변경하지 않았다.
요약은 `data/current_speed_hazard_verification/summary.json`,
전체 결과는 `regression_unrestricted.xml`, 기존 실패 재현은 `head_layout.xml`,
최종 집중/통합 결과는 `final_focused.xml`·`integration_unrestricted.xml`에 있다.
