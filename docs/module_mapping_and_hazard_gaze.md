# 모듈별 영역 확인 및 위험사건 이전 시선 집계

2026-10-20. 통합 파일럿 런처의 다음 새 실행부터 적용한다. 실행 중인 실험이나
언리얼을 재시작하지 않았다. 차량 제어·핸들/페달 입력·NoA 해제·깜빡이 진출·
위험사건 생성/경고/충돌 처리 코드는 이번 범위에서 변경하지 않았다.

## 전체화면과 모듈 시작 전 확인

- 전체화면 자동 적용·유지와 모니터 위치 고정은 제거했다. `run_pilot.cmd`는
  창 모드로 시작한다. 주행/검사 창을 원하는 모니터로 옮긴 뒤 F11을 눌러
  해당 모니터의 전체화면으로 전환한다. F11을 다시 누르면 창 모드로 돌아간다.
  논리적 주행 화면과 카메라/AOI 배치, 기존 비율 유지 확대는 유지한다.
- M1과 M2 안내에서 SPACE를 누르면 각각 짧은 영역 확인으로 진입한다.
  전방 → 좌측 미러 → 우측 미러 → 실제 태블릿 중앙 → 전방을 확인한다.
  각 지점 준비 1초·측정 5초이며, 기준과 최대 3회 재검사는 기존과 같다.
  개인 ETM 보정을 대체하거나 매 모듈 새 보정을 자동 수행하는 기능은 아니다.
- 검사 화면에서는 F11로 모니터를 조정할 수 있고, 측정은 전체화면에서만 시작한다.
  검사도 창 모드로 시작하며, 측정 중 포커스 상실·전환은 해당 검사를 무효화한다.
  검사한 모니터 좌표는 시선 검증에만 사용하고 창 위치를 강제로 옮기지 않는다.
- 주행 중에도 F11로 창/전체화면을 전환할 수 있다. 다른 키·핸들·페달 이벤트는
  유지한다. 모듈 전환 후 새 창이 뜨면 같은 주행 모니터에서 F11로 전환한다.
- 각 모듈의 시도·합격·제외 결과를 독립적으로 저장한다. M1 합격을 M2에 재사용하지 않는다.
  불합격이면 F8 → ENTER로 제외할 영역을 확인한 후 계속 진행할 수 있다.
  ESC는 모듈 안내로 돌아간다. `--no-gaze`는 기존처럼 영역 검사를 생략한다.

## 매핑 증거와 오류

검사 결과에는 모니터 이름/영역, 창 내부 영역, 실제 표면 해상도, DPI를 저장한다.
전체화면의 실제 좌표를 읽지 못하면 타깃 비율만으로 합격 처리하지 않는다.
주행 수집기에서는 같은 증거를 대조하며, SDL이 다시 만든 창의 HWND 번호만
달라진 것은 오류로 보지 않는다. 창 모드 시작/수동 전환 구간은
`FULLSCREEN_MAPPING_REQUIRED` 사유의 `MAPPING_UNAVAILABLE`로 기록하고,
검사한 전체화면 좌표가 복원되면 분류를 재개한다. 이 구간만으로 모듈 전체를
영구 제외하지 않는다. 다른 모니터의 시선은 `TRACKER_MONITOR_MISMATCH`로
구분하고, 동일 모니터 전체화면의 DPI·물리적 표시 영역·렌더링 종횡비 변경 등 실제 검증 오류는
`MAPPING_VALIDATION`으로 남겨 해당 모듈 AOI 분석값을 제외한다.
설정에 모니터가 지정되지 않았다면 사전검사에서 진행자가 선택한 전체화면
모니터를 사용한다. 명시한 장비 모니터 설정은 자동으로 덮어쓰지 않는다.
원본 시선과 미매핑 구간은 유지한다. 정상 종료 직후의 창 조회를 피하는 기존
수명 처리도 유지하며, 실제 GetClientRect/저장 오류를 성공으로 바꾸지 않는다.

### 4K 모니터와 FHD 렌더링

전체화면 여부는 Windows의 물리적 모니터 영역과 창 내부 영역으로 판단한다.
두 영역이 3840×2160이고 SDL 표면이 1920×1080인 경우도 정상이다.
렌더링 해상도 자체를 물리적 화면 크기와 같게 강제하지 않는다.
시선 좌표는 모니터 정규화 좌표 → 물리적 창 내부 → SDL 표면 → 비율 유지
확대 영역 → 논리적 주행 화면 순으로 변환한다. 검은 여백은 AOI에 포함하지 않는다.
사전검사와 주행의 모니터·물리적 표시 영역·DPI가 같고 렌더링 종횡비가 같으면
FHD/4K 표면 전환을 허용한다. 다른 종횡비·장비 표시 영역을 새 검사 없이
동일한 매핑으로 인정하지 않는다.

창을 두 모니터에 걸쳐 옮기는 동안은 `WINDOW_SPANS_MONITORS`로 남긴다.
기존 250ms 조회 간격으로 다시 확인하며, 검사한 전체화면으로 돌아오면 분류를
재개한다. 창 이동·F11 기능 자체는 수정하지 않는다. 이동·포커스 상실·전환 중
매핑 불가 구간을 특정 AOI로 채우지 않는다.

### 데이터만으로 영역 확인하기

각 수집 폴더의 `gaze.jsonl`은 다음 정보를 함께 담으며 결과 ZIP에도 포함된다.

- `metadata.aoi_schema`: 좌표계, 영역 이름, 관측 상태, 분석 자격 해석.
- `gaze.aoi`: `FORWARD` 전방, `LEFT_MIRROR` 좌측 미러,
  `RIGHT_MIRROR` 우측 미러, `TABLET` 외부 태블릿. 나머지는 `NO_AOI`.
- `gaze.mapping_id`로 같은 파일의 `mapping.mapping_id`에 연결한다.
  해당 ID의 `definition`에는 물리적 모니터·창 영역, SDL 해상도, 논리적 화면 크기,
  확대 영역, 전방 다각형·미러 사각형, 논리 좌표→모니터 정규화 변환식이 있다.
  동일 형상은 정의를 반복하지 않고 ID로 연결한다.
- `gaze.render_point`는 논리적 화면 픽셀 좌표다.
  `screen_gaze_display_normalized`는 화면 안에서 유효한 눈 좌표의 평균이다.
  원본 좌우 눈 좌표와 SDK 원자료도 그대로 남는다.
- `gaze.tablet_profile_sha256`는 같은 파일의 `tablet_profile.sha256`에 연결한다.
  태블릿은 좌우 눈별 경험적 다각형으로 판정한다. 이 좌표는 모니터 표시 평면을
  확장한 Tobii 좌표이며 실제 태블릿 픽셀 좌표가 아니다.
- `observation_state`는 `TRACKING_LOST`(추적 손실),
  `MAPPING_UNAVAILABLE`(화면 매핑 불가), `VALID_UNMAPPED`(지정 영역 밖),
  `AOI_UNCERTAIN`(눈별 불일치/화면·태블릿 충돌)을 구분한다.
  매핑 불가 행의 `mapping_id`는 null이고 `mapping_reason`에 사유를 남긴다.
- `analysis_aoi_included`와 모듈 사전검사 결과로 분석 포함 여부를 확인한다.
  영역으로 분류된 원자료가 있어도 해당 영역 검사에 불합격했다면 분석 합격을 뜻하지 않는다.

Tobii 표시 평면은 좌상단이 (0,0), 중앙이 (0.5,0.5), 오른쪽·아래쪽이 양의 방향이다.
태블릿 좌표는 [0,1] 밖일 수 있다. 룸미러는 현재 비활성 배치이므로
`mapping.definition.screen_regions_logical`에 포함되지 않는다.
이 수정은 해상도 변환 오류를 고치는 것으로, 개인 보정·태블릿 추적 손실을
복원하거나 불합격 검사를 강제로 합격시키지 않는다.

저장 위치는 실행 결과 폴더 아래다. 완료된 파일은 결과 ZIP에도 들어간다.

| 파일 | 확인 내용 |
|---|---|
| `gaze_precheck/M1-*/check_summary.json` | M1 영역별 판정과 실제 화면 매핑 |
| `gaze_precheck/M2-*/check_summary.json` | M2 영역별 판정과 실제 화면 매핑 |
| `m1_gaze_quality.json`, `m2_gaze_quality.json` | 해당 모듈의 진행자 결정·제외 영역·매핑 증거 |
| `gaze/MODULE_1_RUNNING-*/summary.json`, `gaze/MODULE_2_RUNNING-*/summary.json` | `display_mapping_checked`, 예상/마지막 매핑, 오류·영역별 자격 |

`aoi_validated`는 해당 모듈 사전검사 전체 합격, 실제 주행 화면 매핑 확인,
모든 영역의 분석 자격 유지가 함께 충족될 때만 true이다. 전체 주행에서 한 번도
추적 손실이 없었다는 뜻은 아니다. 부분 합격 영역은 `gaze_precheck.eligible_aois`로
따로 확인한다. `status=COLLECTED`만으로 영역 정확도 합격을 추정하지 않는다.

## 위험사건 이전 시선 집계

새 `CLEAR_ROAD_STABLE_TARGET_SPEED_NO_LEAD` 사건은 지하 준비 중에는 눈에 보이는
앞차/장애물이 없으므로, `m2_hazard_display_candidate`의 첫 화면 flip 시각에서
위험사건 이전 구간을 끝낸다. 해당 시각 이상인 샘플은 `before_hazard`에 포함하지 않는다.
QPC 기록이 있는 실행은 `flip_completed_perf_counter_ns`를 공통 시계로 사용한다.
이전 시계만 있는 실행의 새 사건은 실제 `flip_completed_monotonic_ns`를 사용하며,
이벤트가 파일에 기록된 시각으로 대체하지 않는다.

- 구형 앞차 사건은 기존 `m2_hazard_preparation_started` 기준을 유지한다.
- 경계 시각/필요한 시계가 없으면 `BOUNDARY_UNAVAILABLE` 또는
  `BOUNDARY_CLOCK_UNAVAILABLE`로 남기고 사건 이전 분석값·구간 길이는 null이다.
  원본과 `all_active_m2` 집계는 유지한다.
- 장애물 제시 증거 없이 `m2_hazard_not_occurred`가 명시된 경우에만
  `CONFIRMED_NOT_OCCURRED`로 전체 활성 주행 구간을 사건 이전 구간으로 취급한다.
- 손실 구간을 태블릿 주시로 채우거나 사건 경계를 넘겨 시간을 보간하지 않는다.

`collection/m2_gaze_metrics.json`의 `captures[].hazard_boundary`,
`hazard_exclusion_start_s`, `hazard_exclusion_policy`, `cohorts.before_hazard`에
사용한 경계·시계·판정과 결과를 남긴다. 기존 원본 CSV/JSONL은 수정하지 않는다.
보고서 생성 오류는 기존 비중단 처리에 따라 진단으로 남긴다.

## 검증

4K/FHD 매핑 보완 후 오프라인 검증(2026-10-20): **678건 통과, 기존 실패 5건, 1건 건너뜀**.
새 매핑 회귀 29건을 포함한다. 모니터 위치·DPI·렌더링 크기·검은 여백,
M1/M2 사전검사, 수동 F11 왕복·모니터 간 이동 후 분류 복원,
매핑 증거 저장 실패 시 비중단 처리, 네 영역/미분류 상태와 ZIP 내 증거를 확인했다.
기존 실패 5건은 콕핏 위치·미러 높이의 이전 값을 기대하는 검사이며, 보완 전
소스를 별도 Python 프로세스에서 불러와 같은 실패를 재현했다.
건너뛴 1건은 환경의 심볼릭 링크 생성 제한이다. 저장 권한으로 막힌 검사는
샌드박스 밖의 동일한 오프라인 검사에서 통과했다.
상세 결과: `data/scaled_mapping_verification/summary.json`.
실제 주행·Tobii 장비를 조작하지 않았으므로 다음 실행에서 개인별 영역 확인이 필요하다.

전체화면 자동 적용·유지 제거 후 오프라인 회귀: **346건 통과**.
`data/manual_fullscreen_verification/tests.xml`에서 344건 통과했고,
ZIP 파일 연결 권한 제한으로 실패한 2건은 일반 권한으로 재검사하여
`data/manual_fullscreen_verification/export_checks.xml`에서 통과했다.
창 모드 검사 시작, 수동 F11 왕복/현재 모니터 선택, 창 전환 중 시선 미매핑 후
정상 분류 복원, 모듈별 사전검사와 실제 매핑 오류 제외, 기존 입력·NoA·
위험사건 이전 시선 집계·ZIP 저장을 확인했다. 실기기는 조작하지 않았다.

전체화면 유지 제거 전 오프라인 회귀: **436건 통과, 1건 건너뜀**.
결과: `data/module_mapping_verification/final.xml`.
CARLA Client와 물리 조이스틱 접근을 금지하고 SDL dummy 화면을 사용했다.
검사에는 모듈별 검사 선행/취소/독립성, 매핑 증거 누락·변경 시 제외,
전체화면 상태의 일반 입력 전달과 센서 유지, 기존 NoA 해제·깜빡이 차선 변경,
위험사건·충돌 후 저장·ZIP, 실제 표시 시각 경계와 원본 불변 검사가 포함된다.
초기 ZIP 검사의 샌드박스 WinError 5는 일반 권한의 같은 오프라인 검사에서 통과했다.

NoA 네이티브 SHA-256은 이전과 동일하다:
`f69e59a5298414f68ec1a27d2d5f820961fc0a7d3a9f0195c4dac6977e43a0b5`.
실제 65인치 모니터·Tobii·핸들 장비를 이용한 검증은 수행하지 않았다.
다음 파일럿에서는 창을 큰 모니터로 옮겨 F11 전환, 해당 모듈 시선 summary의
매핑 증거와 오류, 실제 장애물 표시 시각에서 끊긴 사건 이전 집계를 확인한다.
