# P8 로그 수집 보완 (2026-10-19)

`run_pilot.cmd`의 실행·입력·NoA 해제·위험사건 제어는 그대로 사용한다.
SuRT는 운영자의 별도 Android 앱에서 수집한다. PC가 과제를 새로 표시하거나 앱을 조작하지 않는다.

## 저장 위치와 실행

기존 실행 명령은 `C:\dev\carla`에서 ` .\run_pilot.cmd`이다.
M1 SuRT 조건이 필요한 경우 기존 옵션 ` .\run_pilot.cmd --m1 SURT`를 사용한다.
이 옵션은 조건을 기록하며 **별도 SuRT 앱을 자동 실행하지 않는다**.

새 집계 파일은 `data/p8_operator/<Run ID>/collection/`에 저장되고 결과 ZIP에 포함된다.
원본 CSV, raw_gaze.jsonl, gaze.jsonl 및 기존 세션 매니페스트를 기준으로 종료 후 계산한다.
주행 중 추가 CARLA 조회·입력 읽기·반응 판정 제어를 하지 않는다.

| 파일 | 내용 | 결측 및 한계 |
|---|---|---|
| `clock_sync.json` | Tobii SDK system 시각→Windows QPC→PC 세션 시각의 offset, drift, 잔차, 구간; 실제 시뮬레이터 기록에서 고른 5개 대조 기준점 | 장치 간 물리적 동시 신호 검증이 아님. 태블릿 시계는 미연결이며 3개 시계 검증은 false |

## 시계 정의

- 세션 기준: PC 부모 프로세스의 monotonic ns 및 세션 origin. UTC는 대조 정보이며 두 장치의 시계가 맞음을 보장하지 않는다.
- Tobii worker의 Python 3.10 monotonic과 부모 Python 3.12 monotonic은 Windows에서 원점이 다를 수 있어 직접 빼지 않는다. 기존 SDK clock_pair의 QPC와 수신 시 부모가 기록한 clock bracket을 각각 적합한다.
- 소프트웨어 적합 점검: 최소 5쌍, 4초 이상, 최대 잔차 10ms 이하, bracket 반폭 20ms 이하, 절대 drift 2000ppm 이하. 이는 기록 품질 점검용 버전 1 기준이며 논문 수준의 정확도 검증 기준으로 승인된 것은 아니다.
- 두 적합이 통과하고 해당 구간 안에 있는 표본만 SDK 수집 시각을 정렬한다. 실패/범위 밖에서는 새 기록의 parent/QPC callback 근사 시각을 별도 표시하며, 둘 다 없으면 정렬 불가로 남긴다.
- 시뮬레이터 시간은 프레임과 기존 host capture bracket을 함께 보존한다. 게임의 진행 속도 차이는 장치 시계 drift로 해석하지 않는다.
- 5개 기준점은 **기존 프레임 시각을 기반으로 만든 사후 대조점**이며 태블릿·모니터·센서에 공통으로 물리적 신호를 가한 검증은 아니다. 별도 SuRT 앱은 현재 동기화 근거가 없으므로 3개 시계 전체 합격을 표시하지 않는다.

## 시선 분모·시간·제외

비율 분모는 활성 M2 주행 중 양쪽 눈 중 하나 이상이 SDK-valid인 표본이다.
외부 태블릿처럼 display 좌표 [0,1] 밖의 유효 시선도 분모에 포함한다.
AOI 불명·좌우 눈 불일치·창 매핑 실패를 태블릿으로 치환하지 않는다.
`tracking_loss_sample_ratio`는 수신 표본 중 추적 실패 비율이다. 수신 자체가 멈춘 시간은 별도 `unobserved_or_gap_seconds`로 기록한다.

관측 시간은 같은 상태/AOI의 연속 표본 간 간격만 누적한다(최대 간격 100ms, 순번 연속 필요).
추적 단절·표본 누락·상태 전환 시간을 임의로 연장하지 않는다.
따라서 태블릿 관측 시간은 확인 가능한 시간이며 실제 총 주시 시간의 완전한 측정값은 아니다.
태블릿 오른쪽 모서리 추적 약점도 자동으로 보완됐다고 간주하지 않는다.

위험사건 제외 코호트는 준비 시작부터 M2 끝까지를 보수적으로 제외한다.
위험사건 이후 회복 주행을 포함시키는 연구 정의가 정해지면 원본으로 재집계할 수 있다.
부분 종료는 실제 관측된 구간만 기록하며 완주 780초를 가정하지 않는다.

## 위험사건 반응 정의

- 기준 시각: 프레임이 대응된 화면 flip 완료 시각의 노출 후보. 실제 피험자 인지 시각은 아님.
- 창: 이후 5초. 직전 250ms 내 기준 입력이 있어야 완전한 반응 분석에 포함한다.
- 브레이크: 기준 입력 <0.05에서 ≥0.05로 올라와 100ms 유지. 이미 밟고 있었다면 새 반응으로 기록하지 않는다.
- 조향: 기준 입력 대비 정규화 입력 변화량 ≥0.05를 100ms 유지. 핸들 도수나 NoA 해제 임계값을 바꾸지 않는다.
- 250ms를 넘는 입력 공백이 있으면 분석용 반응시간은 null이며 관측된 후보는 따로 보존한다.
- 무반응, 기존 브레이크 입력, 기준/관측 부족, 노출 미관측을 각각 다른 상태로 기록한다. 반응시간 0으로 대체하지 않는다.
- TTC는 기존 동일 표본 geometry의 candidate만 사용한다. 자동 브레이크는 NoA 상태의 cached control readback 관측값이며 안전 개입/실제 제동 증명이 아니다.
- 충돌은 실제 기록, 통과는 cargo_passed 기록을 사용한다. 기록 없음이나 부분 종료를 회피 성공으로 만들지 않는다.

## 오류와 운영 점검

P8 실제 실행의 CSV 쓰기·flush 및 매니페스트 저장 OSError는 경고와 손실 횟수로 남긴다.
최소 상태 이벤트는 메모리에도 보관해 디스크 쓰기 실패가 모듈 진행을 중단시키지 않도록 한다.
원본이 불완전하면 분석 자격을 낮추며, 기록 성공을 보장하거나 복구 불가능한 원본을 만들어내지 않는다.
집계 실패도 주행 결과나 기존 충돌 안내/Space 종료 조건을 바꾸지 않는다.
프로세스 자체 종료 뒤에는 supervisor가 저장된 기록만으로 복구하며,
새 수집 버전의 실행은 복사된 pending gaze도 부분 기록으로 집계한다.

실기기 확인 항목:
1. 짧은 파일럿 후 위 파일들이 생성되고 ZIP에 들어가는지 확인한다.
2. clock_sync의 Tobii 적합 상태/잔차와 M2 표본의 시간 기준을 확인한다.
3. 전방·미러·태블릿을 번갈아 보며 비율 변화, 추적 실패와 공백 분리를 확인한다.
4. 기존 조향/페달, NoA 해제, 위험사건 충돌 안내와 Space 종료를 확인한다.
5. SuRT 앱 원본과 `surt_external_link.json`을 같은 피험자·실행 묶음으로 보관한다.

오프라인 회귀 테스트는 CARLA Client와 실물 joystick 생성을 금지한 전용 테스트 실행기로 수행한다.
실제 장비에서의 동기화 정확도·수집 품질은 다음 파일럿에서 확인해야 한다.
